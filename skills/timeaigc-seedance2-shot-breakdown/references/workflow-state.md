## 1. 状态块

在每次回复末尾维护以下简短状态，不输出空泛总结：

```markdown
### 当前进度

- 当前阶段：步骤一待确认 / 资源待准备 / 待选拆解范围 / 步骤二进行中
- 步骤一方案：v2（待确认 / 已确认）
- 步骤一方案文件：绝对路径/state/step1-plan-current.md
- 片段版本：01@v1，02@v1，03@v2
- 全局风格：待提供 / 待确认 / 已确认（绝对路径）
- 资产状态：待提供 / 有缺口 / 已就绪 / 用户明确声明无资产图
- 资产目录：绝对路径
- 本片资产：复用角色甲（路径、版本）；新读旧车站（路径、版本）
- 有效分镜：片段 01@v1、片段 02@v1
- 过期分镜：片段 03@v1（步骤一已修改，需重拆）
- 未拆片段：04–08
- 下一步：请补充角色乙资产图和全局风格提示词
```

只列出当前任务中真实存在的状态。路径必须是可复用的绝对路径；片段较多时合并连续编号。

## 2. 正常状态转换

```text
收到剧本
→ 输出含出场角色的步骤一方案 v1
→ 等待用户修改或确认
→ 用户明确确认
→ 保存完整步骤一确认版
→ 收集并检查人物/场景资产图
→ 确认并保存用户提供的全局风格提示词
→ 更新项目 AGENTS.md 与当前状态，输出步骤二新对话交接提示词
→ 在新对话恢复已确认状态（也可留在原对话）；范围未定时询问步骤二范围
→ 核对方案、风格与本片资产版本，复用已知内容并按缺口补读
→ 按指定范围拆镜（默认一次一个片段）
→ 等待下一个指令
```

即使用户首次说“片段和分镜都要”或“全部完成”，也在步骤一后停下。即使用户明确跳过步骤一确认，也不能跳过资源准备门。

## 3. 步骤一确认与落盘

可以视为明确确认：

- “步骤一没问题，确认。”
- “按 v2 继续。”
- “片段方案定稿。”

不能单独视为确认：

- “继续。”
- “开始吧。”
- “差不多。”
- 针对某个局部问题的回答，但没有确认完整方案。

用户确认后，立即按 [asset-workflow.md](asset-workflow.md) 保存完整版本和当前版本文件，再进入资源准备；不能先询问拆镜范围。步骤一没有成功保存时保持阻塞。

## 4. 资源准备门

在同一条消息中向用户索取：

1. 步骤一涉及的全部人物与场景资产图：直接发图、给资产文件夹路径，或明确声明没有资产图；
2. 影片整体风格；
3. 用户编写的完整全局风格提示词。

根据步骤一列出角色与场景检查表。收到直接图片后自动整理并记录路径；收到文件夹后建立映射。以下状态全部满足才能离开资源准备阶段：

- `step1-plan-current.md` 存在并可完整读取；
- `global-style-prompt.md` 已保存用户确认原文；
- `asset-manifest.md` 已覆盖所有角色和场景，或记录用户明确声明无资产图。

资产仍缺失、映射不清、路径失效、图片无法打开或全局风格未确认时，不生成任何分镜，也不把缺失项当作默认值。

## 5. 选择步骤二范围

资源准备完成后，按资产工作流第 8 节提供新对话交接提示词；范围已定则直接携带，未定则由继续拆镜的对话询问，不为生成交接文本提前增加一次选择。用户留在当前对话且没有指定范围时，仍问：

“步骤一、资产和全局风格均已就绪。步骤二要一次性拆完，还是先拆某一个片段？建议先从一个片段开始，便于及时调整。”

若用户回复“逐个来”但没指定起点，从最小编号的未拆片段开始。之后每完成一个片段就停止，等待“下一个”或新的片段编号。

## 6. 返回步骤一

用户在步骤二期间指出片段结构、内容、出场角色、对白归属、时长或场景切分有问题时：

1. 切换到“步骤一待确认”，暂停生成新分镜。
2. 修改用户点名的片段及因边界变化而受影响的相邻片段。
3. 全局方案版本递增，例如 `v1 → v2`。
4. 实际内容发生变化的片段版本递增；只改编号显示而内容未变时，不必递增内容版本。
5. 标记所有依赖旧版受影响片段的分镜为“已过期，需重拆”。
6. 保留未受影响片段的有效分镜。
7. 输出修订后的步骤一片段和状态块，等待用户明确确认新方案。
8. 用户确认后保存新的完整版本和当前版本文件。
9. 若角色、场景或造型映射变化，重新进入资源准备；否则沿用已验证的资产与全局风格状态。

## 7. 影响范围规则

- 修改某片段内部动作、对白、时长或场景：该片段分镜过期。
- 移动片段边界：边界两侧片段分镜均过期。
- 插入、删除或合并片段：所有内容被重新分配的片段分镜过期；仅编号变化但内容不变的结果可保留，并更新编号映射。
- 修改出场角色或场景：依赖变化项的分镜过期，并重新检查对应资产。
- 替换人物或场景资产：使用该资产的分镜过期。
- 修改全局风格提示词：所有已完成分镜过期。
- 只修正步骤二中的摄影措辞且步骤一、资产和风格均未变：停留在步骤二，直接修订该分镜。

## 8. 上下文压缩后的恢复

完整文件仍是有效基线，不凭缺失的摘要重建。新对话从项目 `AGENTS.md` 定位 `state/project-status.md`，恢复已确认事项、有效版本、范围与缺口；不重置阶段、不重复已完成的确认。继续项目或上下文压缩后，当前内容充分且未变化则复用，必要时从以下路径恢复：

1. `state/step1-plan-current.md` 中目标片段及必要前后状态；
2. `state/global-style-prompt.md`；
3. `state/asset-manifest.md` 中适用资产映射与已保存的视觉事实。

核对用户当前指令、方案版本和目标片段。图片按 [asset-workflow.md](asset-workflow.md) 按需补看；不因压缩或进入下个片段重读全部图片。必要文件缺失或内容矛盾时停止，说明具体缺口并等待修复。

## 9. 回到步骤二

用户确认新版步骤一且资源门重新通过后，不默认从头重做。提供三个可执行方向：

- 先重拆过期片段；
- 继续下一个尚未拆解的片段；
- 拆用户指定的其他片段。

开始目标片段前，沿用当前确认的方案、风格和适用资产事实；只恢复缺失或变化的信息。所有新分镜注明依据的 `步骤一方案 vN｜片段 XX@vN`，避免新旧版本混用。

## 10. 异常慢会话的恢复续拆

用户反馈会话持续明显变慢，或已有记录显示操作间长时间等待时，先区分实际工具执行与工具之外的等待。只依据可见记录说明情况；没有计时就不编造阶段耗时，不将界面“正在思考”或重连提示直接认定为推理、图片或用户网络的单一故障。不在每次正常拆镜时额外诊断、扫描全部日志或增加计时调用。

- 先确认哪些文件已保存、哪些校验与总稿同步已完成，是否还有已启动的写入操作未结束；不要把已生成分镜重复拆一遍。无法确认的步骤标为待核对，未校验稿不得记为有效成品。
- 在可操作时更新 `state/project-status.md`，记录当前有效版本、已完成输出、未完成事项和下一步；与正常交付共用这次状态更新，不另建一套交接档案。
- 按资产工作流第 8 节提供针对当前进度的新对话续拆提示词，建议用户在同项目新建干净对话，不复制或分叉整段历史。若当前片段已写好，只待校验、同步或交付，交接明确从该未完成步骤继续；否则带入已选范围或待选范围状态。
- 不自动中断、创建或切换任务，不强制每段或每固定数量换对话。建议切换前说明仍在进行或状态不明的写入，避免两个对话同时修改同一片段或总稿；不要让用户为一个已保存的结果无限等待最终聊天回复。
- 新对话恢复已有确认、缺图决定、资产视觉事实、必要相邻状态及总稿同步约定，只补核对缺口。正常质量标准、构图站位、原台词和必要校验不因提速而降低。
- 未知延迟不通过擅自改模型、推理档位、网络配置、安装依赖或反复重试处理。需要对照时先用同模型同档位的相同请求比较新旧会话，注明内容、同步范围或时段差异，不承诺固定完成时间或加速倍数。
