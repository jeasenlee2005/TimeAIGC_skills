# MJ V8.2 角色设计提示词

创建可供用户复制到 Midjourney 的角色设计提示词，按“先定脸，再依据定稿图设计全身”推进。每次只交付当前阶段的一条英文提示词，完整可复制文本（含尺寸尾缀）总长度不超过 1024 字符，附中文翻译。此变体不沿用通用 Skill 的正常版与精简版双版本输出。

MJ V8.2 是用户指定的使用目标，1024 字符是本工作流的限制；不把它描述为已经核实的官方平台上限。只编写提示词，不调用生图工具，不自动向 Midjourney 上传或提交。

## 1. 确认输入和全局风格

接收简单人物描述即可开始：保留用户指定的年龄设定、性别表达、时代、身份、性格和关键外观；缺失的美术细节做适度、连贯的设计补全。若尚无人物描述，请用户提供。普通设计细节不需要逐项追问。

在当前角色流程第一次生成前确认全局风格。若上下文尚未明确，询问并等待：

> 你是否有需要复用的全局风格提示词？如有，请完整粘贴；如没有，请回复“没有”。

- 已说明没有、已提供完整风格，或明确沿用当前流程的风格时，直接继续；第二阶段不重复询问。
- 只说“有”但未提供文本时，等待完整文本；不先生成角色提示词。
- 英文风格：原文作为固定前缀，完整、逐字不变地放在每条英文提示词正文最前面，包括大小写、标点和内部重复，不润色或重排。
- 中文风格：忠实、完整地翻译成英文，不增加、删减或改变要求；将译文确定为固定英文前缀，并在两阶段沿用同一译文。中文说明保留用户中文原文。
- 中英混合风格：翻译中文部分，保留已有英文内容；以完整英文结果作为固定前缀，中文说明附完整输入原文。
- 固定前缀只有在用户修改风格后才更新；第一阶段的完整角色提示词不是全局风格，不能整段复制为第二阶段前缀。
- 后续描述对全局风格做语义去重，避免重复媒介、渲染方式、色调、光质和画质。不得误删当前阶段的主体、构图、身体、服饰或辨识特征。七项信息可以由前缀和后续描述共同覆盖。
- 全局风格若与灰背景、景别、正面站姿、柔光等当前阶段要求存在实质冲突，简要指出具体冲突并等待用户调整；不得静默改写固定前缀。全局风格前缀不承载命令参数；若其含命令、尾缀，先请用户提供纯风格文本，当前阶段的尺寸参数统一按输出协议置于文末。

## 2. 第一阶段：肩部以上头脸特写

依据人物描述，生成用于确定头部和脸部外观的一条英文提示词。

画面必须满足：

- 单个人物，3:4 竖幅构图，肩线附近裁切，画面集中于头部、脸部和少量颈部；不展示躯干或全身。
- 完整头部和主要发型轮廓入镜，头顶留少量余量；避免会把额头、头发或下巴切掉的极端局部特写。
- 默认平视、脸部正对镜头、五官清晰，自然神态；结合用户人物设定体现适度表情。
- 均匀纯灰色背景，无场景、图案或杂物；柔和均匀的光线让头脸细节可读。

描述重点为脸型与颌线、颧骨、眉形、眼形和眼色、鼻梁、嘴唇、肤色与皮肤质感、发色发型、发际线，以及用户指定或设计所需的胡须、雀斑、痣、疤痕或头饰。选取能形成辨识度的特征，不必逐项堆满；不要自动给所有人物增加疤痕或配饰。服装最多简述画面边缘可见的领口，优先把字符留给头脸。

用 `shoulders-up head-and-face close-up`、`entire head visible`、`solid gray background` 等自然英文表达构图意图，避免同时出现胸像、半身照或全身镜头要求。3:4 是尺寸设置，默认在完整提示词末尾添加 `--ar 3:4`；用户要求纯描述时，按输出协议单独说明比例。

生成后停留在第一阶段。用户提出修改时只修订该阶段，并重新计数。末尾简短提示：“请确认这版头脸特写提示词；通过后，请上传你最终选定的特写成图，再继续全身立绘。”

## 3. 阶段转换与定稿图

进入第二阶段前，需同时具有：用户对特写设计的认可，以及可实际查看的最终特写成图。

- 用户只说“通过”但没有图片：请其上传最终特写图并等待，不凭第一阶段文字直接编写全身版本。
- 用户提供图片并说“定稿”“用这张做全身”等，视为已确认，无须再次走确认环节。
- 同一流程中用户按上一轮要求上传一张特写成图，且没有要求继续改脸，可视为选定该图并继续。多张候选图没有指定哪张时，只询问选用哪张。
- 先实际查看图片；本地图片用可用的图像查看工具打开。无法读取时说明缺失并等待可读图片，不声称已经观察。
- 在当前对话保留已确认人物设定、最终图、全局风格原文及英文前缀，供后续修订沿用；不另建用户未请求的项目或外部存储。

## 4. 第二阶段：全身正面立绘

以选定特写图为头脸身份依据，以用户最新要求和已确认人物设定为身体、服装设计依据。保留发色发型、面部轮廓及少量关键辨识特征。图中实际生成的头脸特征优先于先前文字中的未实现细节；用户明确要求再修改的部分除外。

画面必须同时满足：

- 单个人物，全身镜头，9:16 竖幅；从头顶到双脚完整入镜，脚部及鞋履清楚可见，脚下留少量空隙。
- 正面直立，身体和脸均朝向镜头，正视镜头，自然表情，放松而稳定的站姿。
- 双臂自然垂下、双手位于身侧并可见；不要交叉抱臂、插兜、举手、侧身或摆动态姿势。
- 简单干净、克制的高级灰色背景，柔和光照，无场景杂物；可有轻微自然落地阴影以稳定站姿。
- 4K 高清细节观感，人物整体清晰，身体、服装面料、接缝和鞋履可读。

字符分配优先给身体比例、体型、肩腰轮廓、四肢、服装层次与剪裁、面料材质、颜色、纹样、腰带配件、裤裙、鞋袜等。头脸只用一个短分句概括最关键特征；不得重复第一阶段的五官细节清单，也不得遗漏决定身份的明显特征。

图片未展示的身体、下装、鞋履等，应根据角色设定进行合理设计；这是补全设计，不宣称来自图中观察。用户未要求时不增加手持道具，以维持双手自然下垂和干净背景。

用 `full-length front view`、`standing upright, looking directly at the camera`、`relaxed hands at the sides`、`head to toe fully visible, both feet in frame`、`clean refined gray background`、`soft light`、`crisp fabric and footwear detail` 等表达要求；有等义信息时合并措辞。不要继续使用肩部以上裁切或人脸特写词。9:16 是尺寸设置，默认在完整提示词末尾添加 `--ar 9:16`；用户要求纯描述时单独说明。4K 作为中文规格中的清晰度目标单独列出，不编造分辨率尾缀。

不把“与参考图相同”当作全部人物描述，也不假定图片已上传到 MJ。需要简洁说明时，可在中文末尾提醒沿用定稿特写图作为用户端参考，避免承诺只靠文字就能锁定完全一致的脸。4K 是画质目标，不保证实际输出文件的分辨率。

## 5. 字符限制与交付前核验

每条完整可复制英文提示词最多 1024 个字符，计入全局风格前缀、自然语言正文、连接空格、标点及尺寸尾缀（例如末尾的 ` --ar 3:4`）；不计 Markdown 标题、字符统计、中文翻译或单独的设置说明。按 Unicode 字符计数，不能按单词或 token 估算。

先写当前阶段提示词并按所选方式处理尺寸，再使用 [scripts/check_prompt.py](scripts/check_prompt.py) 实际计数。将最终可复制文本及可选固定前缀作为 JSON 输入，例如 `{"prompt": "固定英文前缀 完整英文描述 --ar 3:4", "prefix": "固定英文前缀"}`；没有全局风格时省略 `prefix`，单独设置模式则不在 `prompt` 中添加尾缀。通过标准输入传入，或使用 `python scripts/check_prompt.py --file <UTF-8 JSON 路径>`，脚本路径相对本 Skill 目录；使用环境可用的 Python。用安全的结构化输入或正确 shell 引用保留精确文本，不因传参改写原文。

脚本只验证字符数和前缀；仍需人工检查阶段要求、画面一致性和翻译。如果 Python 不可用，用等效程序实际计数，不凭目测声称通过。交付前任何英文改动都需要重新计数；仅在检查通过后显示实际的 `N / 1024`。

超长时先压缩后续描述中的重复修饰、空泛画质词和次要设计补全，保留当前阶段必需构图及用户指定的辨识特征。优先使用紧凑自然的视觉短语，不为了填满额度增加内容。

固定全局前缀不可为满足长度而擅自截短。若只有尺寸尾缀导致超限，可以采用单独设置模式，仍明确告诉用户正确比例；若前缀加上当前阶段必需描述本身也无法容纳在 1024 字符内，即使前缀本身未超限，也应简要说明空间不足，请用户提供较短的全局风格版本或明确允许缩短；先等待，不交付超限或缺失硬要求的提示词。

## 6. 输出协议

确认输入、风格及阶段门槛后，只输出当前阶段的一条英文提示词与中文对照。尺寸比例必须使用以下一种方式表达，默认使用尾缀方式：

- 尾缀方式：自然语言描述结束后，先加一个空格，再追加第一阶段的 `--ar 3:4` 或第二阶段的 `--ar 9:16`。尾缀只出现一次，放在完整英文提示词绝对末尾，后面不再加句号或其他描述；字符统计包含它。
- 单独设置方式：用户要求无尾缀、纯描述或单独提醒时，英文提示词只包含画面描述；在提示词外单独写“尺寸设置：3:4 竖幅，请在 MJ 界面设置。”或“尺寸设置：9:16 竖幅，请在 MJ 界面设置。”不得省略尺寸提示。

自行编写的自然语言正文不要再写 `vertical 3:4 composition`、`vertical 9:16 composition`、`3:4 aspect ratio` 或其他把尺寸数字当画面内容的表达。可保留“竖向构图”的视觉意图，但精确比例只放在尾缀或单独的尺寸设置行。

除上述尺寸尾缀外，不自动添加 `/imagine`、`--v`、权重、图片 URL 或其他命令。第二阶段的 4K 仅作为单独的清晰度目标说明，不写成未经确认的分辨率参数，也不把画质参数当作分辨率保证。
