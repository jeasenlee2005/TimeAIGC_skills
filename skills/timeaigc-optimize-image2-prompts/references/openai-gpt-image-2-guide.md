## GPT Image 2 参数摘要

官方指南在核对日期列出：

- `quality` 支持 `low`、`medium`、`high`。
- `low` 适合速度与批量试验；密集文字、精细信息、身份敏感编辑或高分辨率输出应比较 `medium` 与 `high`。
- 尺寸两边都必须是 16 的倍数。
- 最长边必须小于 3840px。
- 长短边比例不得超过 3:1。
- 总像素必须介于 655,360 与 8,294,400 之间。
- 超过 `2560x1440` 的输出更具实验性，结果可能更不稳定；该尺寸可视为常用可靠性上界。

常用参考尺寸：

- 方形：`1024x1024`
- 竖幅：`1024x1536`
- 横幅：`1536x1024`
- 16:9：`2560x1440`
- 2.39:1 可使用满足约束且边长为 16 倍数的尺寸，例如 `2560x1072`

官方模型表说明 `gpt-image-2` 已默认高保真，`input_fidelity` 对该模型不生效；但同一指南的部分示例代码仍出现 `input_fidelity="high"`。遇到这种文档内部不一致时，不主动为 GPT Image 2 推荐该参数；以当前模型页、API 参考和实际接口验证为准。

## 官方提示基本原则

### 1. 保持稳定顺序

按“背景/场景 → 主体 → 关键细节 → 约束”组织提示。复杂请求使用短标题和换行，便于维护与排错。提示格式本身不是关键，清晰意图和约束比特殊语法更重要。

### 2. 使用具体、可观察的描述

明确材质、形状、纹理和视觉媒介。只添加有针对性的质量线索，例如胶片颗粒、笔触或微距细节。写实任务可直接使用 `photorealistic`、真实摄影或真实相机拍摄等表述。

详细相机参数可能被宽松解释，应主要用来控制整体观感与构图，不把它们当成精确物理模拟。

### 3. 明确构图

指定：

- 景别与取景范围；
- 视点与机位角度；
- 透视、主体位置和留白；
- 光线方向、氛围和颜色。

宽幅、电影感、低照度、雨夜或霓虹场景需要额外说明尺度、空气与色彩关系，防止模型为了表面氛围牺牲空间真实感。

### 4. 明确人物动作关系

有人物时说明人物相对尺度、身体入镜范围、视线、姿态，以及手与物体的接触方式。这有助于比例、动作几何和视线对齐。

### 5. 明确改变项与保持项

写出排除项和不变量。编辑任务使用“只改变 X，其他内容保持相同”，每轮重复关键保持项以减少漂移。精细编辑还应锁定构图、相机角度、周围物体、色彩和对比度等不应变化的内容。

### 6. 文字与多图输入

需要准确文字时，把原文放在引号中并指定字体风格、大小、颜色和位置；复杂拼写可逐字母写出。多图输入时按编号描述每张图的角色，并明确从哪张图取什么、放到哪里、哪些内容必须保持不变。

### 7. 小步迭代

长提示可以工作，但排错更适合从干净的基础提示开始，再用单项修改逐步优化。上下文开始漂移时，重新写出关键约束，不只说“和之前一样”。

## 写实摄影建议

把画面描述成真实摄影师正在捕捉的瞬间。使用镜头、光线和取景语言，并描述可信的不完美细节，例如皮肤纹理、材料磨损、褶皱和自然表面变化。避免同时堆叠过度棚拍、重度修饰、夸张锐化等会削弱自然感的词。

对复杂写实场景，将“自然曝光、真实材质、细微胶片颗粒、自然色彩平衡、合理磨损”作为少量有目标的质量线索，不使用一长串同义质量热词。

## 编辑与合成建议

- 草图转写实：保持布局、比例和透视，再加入合理材质、光线与环境；禁止新增无关元素或文字。
- 光线或天气转换：只改变环境条件，同时保持身份、几何、相机角度和物件位置。
- 多图合成：明确移植对象、目标位置和保持项，并匹配光线、透视、尺度与阴影。
- 精细替换：只替换指定对象，保持相机角度、环境光、接触阴影和周围语境。

## 与本 Skill 两阶段流程的映射

以下是基于官方原则的工作流映射，不是官方原文：

1. 第一阶段使用官方的稳定顺序、明确构图和小步迭代原则，先建立完整空间。
2. “结构锚点、叙事道具、材质点缀”是本 Skill 为复杂场景增加的分级方法。
3. “局部化破坏、限定数量、抑制重复”是为解决碎片化画面增加的实践性约束。
4. 第二阶段沿用官方“只改变 X、重复保持项”的编辑原则，再转写成适合 Nano Banana Pro 的保构图增强提示词。
5. 如果第一阶段几何错误，先单项修复结构；不要直接用材质增强掩盖结构问题。
