# TimeAIGC_动态运镜提示词

## 锁定能力边界

- 只设计一个连续视频片段内的镜头运动与画面演绎。默认给出同一素材的三种候选方案，不把三种方案串成分镜。
- 不切分完整剧本，不建立多镜时间轴，不设计长篇打斗动作链，不套用 Seedance 等平台的专属时长或字段。遇到这些任务时，说明本 Skill 只适合其中某个单镜或单片段的运镜细化。
- 不调用外部生成服务，不生成图片或视频。
- 保留用户明确给出的主体、动作、方向、情绪、构图和首尾状态。只补足镜头可执行信息，不新增会改变剧情的角色、对白、道具或事件。
- 区分摄影机位移、机位原地转动、光学变焦与焦点转移。不要把主体靠近镜头误写成推镜头，也不要把变焦镜头写成摄影机位移。

## 读取参考

- 每次生成前读取 [references/camera-motion-language.md](references/camera-motion-language.md)，使用其中的受控术语、首尾帧判断方法和兼容性规则。
- 完成草案后运行 `scripts/validate_motion_prompts.py`。脚本只检查结构、语言和明显的术语冲突；视觉忠实度与可拍性仍须人工复核。

## 判断输入模式

1. **单张图片**：观察主体、前中后景、遮挡、视线、可移动空间、光源和画面重心。把静态画面视为起始状态，只设计不会违背已见事实的轻量动作。
2. **首尾帧图片**：分别记录主体大小、画面位置、朝向、姿态、焦点、背景覆盖范围和遮挡，再判断变化来自摄影机、主体、镜头焦距还是焦点。证据不足时明确写出假设，不把画面差异强行归因于推拉运镜。
3. **文字场景**：提取主体动作、环境尺度、情绪目标、叙事揭示点和结束画面。缺少画幅、时长或画质规格时不必停顿，采用保守表达且不虚构具体数值。
4. **用户指定运镜**：优先执行用户术语；若它与静止机位、首尾帧、空间路径或目标时长冲突，指出冲突并给出最小替代方案。
5. **信息不足**：只要能确定主体与观看意图，就用一行“假设”补齐非关键条件后继续。若连主体或画面内容都无法确定，只询问一个最关键的问题，不生成空泛模板。

以下代表性请求对应不同处理方式：

- “根据这张人物图做三版压迫感运镜。”——按单图模式生成克制、动态、电影感三种候选。
- “首帧是远处赛车，尾帧是赛车特写，做一个极速运镜。”——先判断主体前进与摄影机靠近的相对贡献；无法确认时标注假设。
- “把这份一分钟剧本拆成完整分镜并写运镜。”——不在本 Skill 内执行完整拆镜；只在用户指定某个单镜或单片段后细化运镜。

## 锁定镜头任务

生成前提取并区分：

- **用户明确事实**：主体、场景、动作、方向、必须保持或必须发生的首尾状态；
- **从图片观察**：构图、景别、相对位置、遮挡、光线、材质和可见情绪；
- **执行性假设**：时长、速度、摄影机可移动空间、焦点变化和画面外路径。

再锁定五项：

1. 观众首先看什么，以及镜头结束时注意力落在哪里；
2. 主体的画内运动与摄影机运动分别是什么；
3. 起始构图、运动路径和结束构图；
4. 目标时长、主要运镜、速度曲线、触发点与停止点；
5. 焦点、景深、前景遮挡、光影和环境反馈是否支持主要意图。

## 设计三种候选

默认生成三种真正不同但都忠实于输入的方案：

1. **克制写实**：优先稳定、简洁、接近观察者视角的运动，让主体表演主导。
2. **动态冲击**：在空间和时长允许时增强速度、贴近感或不稳定感，但保持路径清楚。
3. **电影氛围**：通过空间揭示、视点变化、焦点转移或光影层次强化情绪，不为“电影感”强行环绕。

用户指定数量、风格或唯一运镜时，以用户要求为准。若固定机位是核心约束，三种方案都必须保持机位固定，只能通过表演、构图、光线、变焦镜头或移焦镜头形成差异。

对每个方案依次执行：

1. 从参考文件中选择一个主要运镜意图。短片段不要堆叠多个同等强度的运动。
2. 写清摄影机相对主体的方向、距离或高度变化；只写“镜头移动”视为不可执行。
3. 写清起始、触发、运动、主体反馈与结束画面。组合运镜时说明先后顺序和切换触发点。
4. 让焦点与叙事重点同步。使用移焦镜头时明确焦点从谁或什么转到谁或什么。
5. 让主体动作符合输入。除非用户明确要求，不添加对白；图片没有支持的动作不要写成既定事实。
6. 只在确有帮助时补充光影、动态模糊、景深、环境反应和画质描述，不用“高清”“电影级”掩盖运动逻辑。

## 使用受控语言

- 运镜名称只使用参考文件列出的受控术语。速度、方向、稳定度和轨迹可作为修饰语，但不得据此创造新的运镜名称。
- 固定机位时，提示词必须以“固定镜头”开头。固定镜头可以和变焦镜头或移焦镜头组合，但不能与机位转动、空间位移或手持运动同时出现。
- 全文使用中文；`FPV 镜头`是受控专业术语中唯一默认保留的英文缩写。数字分辨率、模型名或用户原文只在用户明确要求时保留。
- 不使用“推拉拍摄”“旋转运镜”“镜头飞舞”等含义不清或不在术语表内的运镜名称。
- 不把剪辑、转场、慢动作、延时摄影或主体运动当成运镜术语；需要时把它们写成独立的画面或节奏说明。

## 输出格式

信息存在推断时，先在代码块外输出一行：

`假设：……`

默认严格输出三个方案，每个方案只含一个标题和一个单段代码块：

````markdown
### 方案1｜克制写实

```
单段中文提示词
```
````

三个方案分别使用独立代码块。代码块内部不要使用标题、列表、加粗、斜体、字段标签或额外解释。提示词按“起始画面 → 运镜与主体动作 → 焦点/光影/环境反馈 → 结束画面”的自然顺序书写，不强制添加数字画质规格。

若用户只要一个方案或指定其他数量，保持相同结构并连续编号。

## 校验与交付

把正式草稿保存为 UTF-8 Markdown 临时文件，并运行：

```powershell
python scripts/validate_motion_prompts.py <临时文件> --expected 3 --report
```

将 `--expected` 改为用户要求的方案数量。修复全部 `ERROR`，逐项复核 `WARNING`，然后删除临时文件。若当前环境不能运行脚本，按同样规则人工检查。

输出前逐项复核：

- 三个方案是否服务同一输入事实，但在观看策略上有实质差异；
- 主体运动与摄影机运动是否被清楚区分；
- 首尾构图是否能由所写路径连续到达；
- 运镜术语是否受控，方向、速度、触发点和停止点是否明确；
- 是否出现固定镜头与机位运动并存、短时长内动作过载或焦点冲突；
- 是否凭空添加对白、角色、道具、事件或不可见细节；
- 代码块数量、编号、单段格式和中文表达是否正确。
