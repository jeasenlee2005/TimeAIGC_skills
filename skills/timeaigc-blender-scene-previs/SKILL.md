# TimeAIGC_Blender场景与镜头预演

把空间布局作为稳定底稿，把外观图作为美术参考，把预演作为机位与调度参考。视频模型只提供参考约束，不能承诺逐帧、像素级或三维一致性。

## 明确入口与授权

- **只做场景**：剧本/场景描述 → 空间数据 → 平面结构图 → 无人简模 → 四机位构图；按请求继续真实场景图，不要求先有完整分镜。
- **只做预演**：已有场景数据/简模 + 定稿分镜 → 机位和演员占位 → 镜头视频。已有 `.blend` 不直接交给会重建场景的脚本；先复制并检查坐标、集合、相机和关键物件，编写项目适配脚本或映射到本契约。
- **完整流程**：完成场景与预演评审后，按授权调用生图/即梦并验证实际产物。
- 用户只给分镜或图片时先识别素材；没有场景事实不能虚构已拆解结果。缺少非关键尺寸可按常见比例推断并记录；影响剧情的出口、通道或层高冲突要解决后再建模。
- 区分“用户确认”“用户授权代理自审”“未确认”。普通流程先展示平面图/四机位与预演，获取影响后续的反馈；用户已明确授权自主完成时自行检查并记录依据，不重复索要确认，也不伪造用户已审片。
- 只有要求真实生成或已有明确授权才提交付费任务。先短片段验证，再增加时长/镜数。任务状态未知时查询原任务，不重提；没有登录、额度或必要平台授权时保存可用交接包并如实说明阻碍，不用模拟视频冒充生成成功。

## 1. 固定场景空间

读取 [空间与分镜数据契约](references/scene-contract.md)。从剧本和实际看过的资产提取建筑边界、门窗、动线、剧情物件、光源和状态。为物件保留稳定 ID，并记录明确事实、资产观察与推断尺寸。

- 采用米、Z向上、XY平面；世界坐标的东西南北只是工作标记，不冒充故事地理方向。每个摄影机下的屏幕左右另行判断。
- 先写 `scene-spec-vN.json`，由同一数据生成平面图与简模。平面图不是另一次自由生图；不把带漂亮线条但尺寸矛盾的图当建模依据。
- 用分段墙为门窗留实际开口，地板、墙厚、门扇开启范围与过道宽度可解释。室内相机留在真实可拍空间，不为广角便利静默删墙；有特殊剖切镜头时单独标注。
- 冲突资产不能同时作为几何依据。明确选用哪份已确认布局，保留旧版并说明修正。不得从四张不一致图声称完成精确重建。
- 基础场景不含演员、宠物或人体代理；时间、灯光、破坏状态改变时建立状态版本，不无故复制整个场景。

## 2. 构建与检查无人简模

读取 [本地执行与环境](references/execution.md)，使用随附脚本或基于契约的项目适配脚本。标准流程：

```text
python scripts/scene_spec.py scene-spec-v1.json --floorplan floorplan.svg
blender --background --factory-startup --python-exit-code 1 --python scripts/build_scene.py -- --spec scene-spec-v1.json --out render-v1 --render all
python scripts/package_previews.py render-v1
```

以上路径以 Skill 为工作目录示意，真实输出写到用户项目目录；调用时使用解析后的绝对路径，不能把产物写进 Skill。

检查 `scene.blend`、`floorplan.svg`、四张独立机位图及 `manifest.json`。四视图指四个覆盖剧情区域的**透视机位**，并非默认正/背/左/右正交建筑图。保留机位坐标、目标点与焦距，让图与场景可复现。至少检查入口、核心动作区、反向视角和关键道具的覆盖；不强制每张塞入所有家具。

自动检查不能代替视觉检查：查看每张图，确认摄影机没有被墙挡住，近远与尺度合理，重要物件可识别。脚本只做保守的采样碰撞检查，不证明所有运动无碰撞。

## 3. 生成场景外观四视图

读取 [外观与视频参考策略](references/generation.md)。按四张独立简模截图逐张生成真实外观，检查后再拼图；优先在后续视角追加已接受视角作为材质参考，但明确其不能覆盖当前简模的几何。

- 当前简模决定机位、透视、门窗、家具位置和轮廓；原资产/已接受美术图决定材质、色彩、时代与照明。不要把有冲突的旧图当第二个空间模板。
- 逐张比对门窗数量、物件相对顺序、遮挡、光源方向和视角覆盖。模型新增门、移位狗窝、重复机位时拒收该张，修正单张提示词重做。
- 保留独立图片和2×2拼图。构图参考、外观图、失效版本分别标明，不把拼图当影片中的分屏画面。
- 只给提示词的任务停在提示词交付；实际出图任务必须保存真实图片，不用程序占位图冒充生成外观。

## 4. 把分镜转为可播放预演

消费现有 Seedance 2.0、2.5、迷你分镜或打斗分镜的定稿，不重新强制上游所有阶段。保存原文与映射关系：每镜原时间轴、景别、相机、目标点、焦距、人物起终点、持物、视线与连续状态。

- 将自然语言人工解释为镜头数据，不能声称脚本自动理解任意中文分镜。普通位移可用随附角色代理；俯身、转身、持物、接触、打斗与破坏应增加明确动作/项目脚本，不能靠两个站立代理声称已验证复杂表演。
- 随附标准脚本支持基础体块、相机位置/目标点/焦距线性变化、切镜及角色根位移；不支持骨骼动画、IK、口型、自动运镜规划或碰撞求解。必要扩展写入项目副本并实际渲染验证，不擅自修改安装 Skill。
- 全片时间从0开始，镜头无缝衔接；JSON时间按预演fps对齐。采用12fps预演时导出24fps只是重复帧，不是新增真实运动精度；快速打斗应提高采样率。
- `scene.blend` 保持无人；每段 `previs.blend` 保存演员和相机。导出干净单画面MP4给模型，编号采样图只用于审查。
- 查看首、中、尾帧和每个切镜前后；复核屏幕方向、相机遮挡、角色路径、道具状态、动作落点与对白预算。原剧本无法完整预演的部分明确标记。
- 修改布局或机位后生成新版本，使受影响截图、预演和生成请求失效；不要拿旧参考生成新版分镜。

## 5. 参考生成与实测

读取 [即梦任务执行](references/dreamina.md)。先查看当前CLI帮助确认真实模型、时长、分辨率与输入上限；上游Skill写“Seedance 2.5/30秒”不代表当前API支持。保持分镜版本与实际执行模型两个独立字段。

- 每份参考声明用途与顺序：视频=镜头/调度，场景图片=外观，角色图=身份；写清蓝色/棕色等代理与真实角色对应。
- 先测试4–5秒的代表性片段；检查成功状态、视频可播放、时长及实际构图/身份/动作后再做更长片段。失败分成接口失败、素材失败、生成效果不合格，针对原因做有限重试。
- 长度超出接口时按动作完成点拆分，每段各自导出相同长度预演；记录前段末态和后段首态。不能仅截提示词，不能把多段拼接说成单次长视频生成。
- 保存请求、素材哈希、任务ID、响应、模型与结果。只在 `gen_status=success` 且已下载检查媒体后报告生成完成；结构保真度另给判断。

## 交付

交付可编辑的平面数据和Blender文件、平面图、四机位构图及外观图（若已生成）、预演MP4、原分镜与映射、生成记录/最终视频（若授权且成功）、简短验收结果与限制。附实际绝对路径链接，不让用户从工具日志找文件。

用 [验收标准](references/acceptance.md) 区分“本地可复现”“生成任务成功”“空间与动作质量通过”。保留明确的失败证据及可继续步骤；不要只展示漂亮成片而隐瞒机位漂移。
