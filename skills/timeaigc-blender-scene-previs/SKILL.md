# TimeAIGC Blender 动态预演 · v2.2

预演表达构图、运镜、尺度、站位及整体路径；角色外观由资产图提供，细节动作、自然步态、手势、表情和对白表演由完整分镜规定。固定简模不是表演结果，不能承诺视频模型逐帧或三维一致。

这是基于 v2.1 的独立本地副本。保留原安装、旧版本、源场景及仓库，不自动安装、推送或上传 Library。合成演示中的确认记录明确标为测试夹具，不能迁移为真实用户确认。实现与复测证据以交付根目录报告为准。

## 1. 先完成项目级角色尺度与简模确认

读取 [项目接入](references/project-handoff.md) 和 [角色登记与尺度](references/character-registry.md)。从用户指定项目或当前目录向上定位 `.timeaigc/project.json`；读取项目现有说明和登记文件。新任务依靠这些文件恢复事实，不依赖聊天记忆，也不要求用户记固定话术。

1. **先找已确认且覆盖全项目的第一阶段完整片段总表；没有合格总表时读取完整剧本。** 只有当前镜头、选中片段或角色局部截图不满足全项目来源。两者都没有时，先请求完整资料并等待；不得依据当前片段猜全项目人物、默认补身高或继续正式角色建模。
2. 从完整来源梳理全项目角色和形态，核对已有登记。有效、已确认且无冲突的数据直接复用；首次把所有缺少的身高、模型选择和关键尺寸合为一批询问。此后只问新增、缺失或冲突项，不重复问已经确认的尺寸。
3. 人类身高指**脚底到头顶的总高度，包含头部**。巨型人类沿用同一语义和比例；变身以同一角色下的独立形态记录，不覆盖本体。非人类先确认“已有模型／简化形状代理／占位体”，再按形态问必要尺寸。四足角色分别记录肩高、头顶高、体长、体宽；角、耳、尾等突出物的高度、长度与占地独立登记，不能混入一个含糊“身高”。
4. 保存稳定角色 ID、别名、形态 ID、单位与测量语义、确认状态/来源、模型版本及可用资产的相对路径和哈希。选择已有非人模型时读 [本地模型复用](references/local-blend-models.md)：登记符合静态集合契约的本地 `.blend`、精确集合及实测契约，后续任务直接加载原网格。图片更换、同内容文件改名或整体迁移项目，不自动清除已确认尺寸。模型实际尺寸与登记冲突时提出冲突项，不静默拉伸或重置。
5. 确认场景的实际世界尺度，并在 Blender 中实测校准对象；米制和厘米制都换算为米后验证。只修改单位标签不算校准，禁止重复缩放。尺度不明先问，不能以“看起来合理”替代测量。

项目登记覆盖全部角色；本次片段只载入实际出场的角色/形态。角色固有尺寸与每镜根位置、整体朝向分开保存。改变尺寸、模型版本或几何后，将依赖该形态的预演标记过期，保留旧产物和旧绑定，不重新写历史哈希。

## 2. 接入已确认场景与原分镜

优先只读加载已登记的无人 `.blend`，在新的预演版本目录工作。校验场景版本、源文件哈希、分镜和角色绑定；读取 [执行方法](references/execution.md) 及 [镜头数据契约](references/scene-contract.md)。缺模型或需要改场景时交回角色场景资产 Skill，并传递已有材料；不要为方便重建用户场景或声称已调用未安装能力。

原分镜一镜到底就保持一镜到底，多镜保留原切点和时长；不能为了平台限制擅自拆段。只做部分镜头时保存原时间范围、局部零点映射和相邻状态。完整保存原标题、影调、角色、场景、逐镜构图、动作、手势、表情、对白及声音；观看版简述不能替代原文。脚本不自动理解任意中文剧本，完整角色清点和镜头转换仍需实际阅读核对。

## 3. 使用稳定代理制作双版本

- 人类默认由同一生成器生成圆柱躯干、头、低调鼻部和贴合的浅色正面条；无手脚、肩臀或分节四肢。主要靠固定颜色区分身份，前条只表示朝向。只制作根位移与整体朝向，不加入摆臂、迈腿、抬手、点头、呼吸、持物或口型动画。非人类按登记选择：`existing_model` 只读追加已登记本地 `.blend` 的静态集合，保留原网格；`simple_proxy/placeholder` 按参数重建体块。两条路线不可混称；不支持的已有模型明确停止，不能静默换体块。
- 特殊 `articulated_special` 必须明确选择、设 `allow_special_proxy:true` 并说明 `special_proxy_reason`；旧手部字段不能自动启用。固定四肢不等于关节动画。`closeup_static` 仅为独立手部诊断，始终禁止进入模型干净参考。未实现 IK、接触、碰撞求解、真实步态或表演，不得把测试代理当作这些能力的验证。
- 默认人类的四个眼线/视线 Empty 仅为非渲染、局部固定构造点，不代表真实眼睛、自动凝视或表情。每帧核对局部几何与尺寸不变；记录实际生成器或模型版本、部件、单位和模型哈希。已有模型还须核对集合/契约、稳定网格 ID、拓扑/材质/变换摘要，检查实际单位、正面及地面，禁用资产脚本自动执行。
- 需要复杂相机路径、前景遮挡或多人调度时读 [复杂镜头预演](references/complex-previs.md)。先确定剧情要表达的空间信息，再实现相机与整体路径，仍保留全部原表演文字。
- `scene.blend` 保持无人；演员和相机保存于片段 `previs.blend`。`timeline-v2.json` 用零基整数帧与半开区间，干净/说明版共用原生 fps、帧数与切点。编码加帧率不增加真实运动采样精度。
- 干净 MP4 无文字、编号或说明栏，只有它可进入视频参考白名单。说明版从同一干净 PNG 在下方扩展独立文字栏，原画面不遮挡、不缩放、不裁切；显示每镜简述和完整对白。
- 延续 v2.1：`compact` 与 `--panel-height auto` 选择能满足全片排版及原阅读预算的最小固定栏高；全文展开 `expanded` 需明确选择。中文按字形宽度换行，完整对白可在原镜头内分页，不能截断、延时或插停格。空对白独立显示“（无对白）”，不串前镜。默认无用途警示和重复标签；可选提示不改变 `review-only` 身份。

## 4. 检查真实产物，绑定本次项目状态

按 [验收标准](references/acceptance.md) 核对实际画面：角色正侧背面、颜色身份、完整身高和突出物占地，首中尾、每个切镜前后、长中文对白及静默镜头。每帧核对说明 PNG 顶部与干净源相同，逐字重构对白；两版有损 MP4 必须另做完整解码、帧数、逐帧 PTS 与图像误差检查，不能声称有损编码后逐像素相同。

保存场景实测校准、角色登记快照、只包含本片演员的绑定、源分镜、实际几何记录、全文提示词及覆盖报告。最终生成入口同时检查白名单和当前项目状态；受影响形态已变更或预演过期则重新制作新版本。改变说明栏时仅可在新目录复用已核验的干净视频与时间轴，不能借复用跳过尺度、模型或来源校验。

## 5. 生成材料与授权边界

读取 [视频参考策略](references/generation.md)。提示词明确视频只提供构图、机位、尺度、站位和整体路径，不模仿圆柱外形、无肢体、前条、僵直或滑行；按实际角色 ID/形态/颜色映射介绍素材，保留完整表演及对白。此说明降低误用风险，不保证生成模型不受代理外形影响。

运行 `reference_guard.py` 检查实际文件、哈希、完整源文本与模式/登记绑定；说明版、改名副本、手部诊断和过期绑定不得进入生成清单。验证是受控来源及字节保护，不是自动视频语义鉴定。

默认交付材料供用户自行生成。只有明确授权实际生成时才读 [即梦执行](references/dreamina.md)、核实当前服务参数并提交；状态未知先查原任务，不重提。保留成功响应与实际下载检查，区分“本地可复现”“服务任务成功”和“最终空间/动作质量通过”。本次 v2.2 本地工程交付不调用付费生成或 Library。

## 6. 每次完成后固定提供五项交付入口

每次预演制作或修改完成并通过验收后，在最终回复中集中列出以下五项可点击的 Markdown 链接，保持此顺序和名称；即使过程中已经发过，也必须再次提供，不能只报告完成或让用户自行查找目录。

1. **观看版（含说明与对白）**：链接本次说明版视频，包含镜头说明和完整对白文字；不要把文字对白表述为已有配音。
2. **干净版（生成参考）**：链接本次已核验、可进入生成参考白名单的干净视频。
3. **完整提示词**：链接保留完整分镜、动作表演及对白的实际提示词文件。
4. **素材清单**：链接用户可读的本次素材清单，列明实际使用的干净视频、角色/场景等资产图及各自路径、用途和上传顺序；不存在的素材不虚列。`upload-list.json` 仅是干净视频白名单，不能冒充全部素材清单；必要时另保存完整素材清单并链接它。

   每个素材条目末尾都附独立的定位链接：Windows 标为“在资源管理器中定位”，macOS 标为“在 Finder 中显示”。点击应打开素材所在文件夹并选中该素材文件；仅打开预览、素材文件或所在文件夹都不等于定位选中。各链接分别绑定本条素材的真实绝对路径，正确处理中文、空格和特殊字符，不用一个总目录链接代替逐项定位。

   使用当前宿主已支持且经过验证的文件定位链接或原生动作，交付前核对目标文件与实际定位结果。不得猜造 URL 协议、把内部消息名当成链接，或将普通文件链接标成已实现一键选中。若宿主不提供可点击的定位入口，明确说明限制，仍为每项保留可用的文件链接与绝对路径，并给出已确认可用的宿主定位操作；不要虚称实现了直接选中。

5. **全部交付文件与 Blender 工程入口**：链接本次交付目录或交付索引文件，让用户能找到全部交付文件和实际使用的 `previs.blend`。工程不在该目录时，在交付索引中直接链接真实工程路径；复用干净视频时保留来源说明，不能假设新目录已复制工程。

本地链接使用真实绝对路径；链接前核对文件存在、版本对应本次交付，交付索引中的链接也须核验。多个片段按片段分组提供五项入口。尚未生成、验收失败或缺失的项目明确标为未完成并说明原因，不虚构链接或宣称制作完成。
