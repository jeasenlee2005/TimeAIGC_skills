# TimeAIGC_Blender动态预演

把空间布局作为稳定底稿，把外观图作为美术参考，把预演仅作为构图、运镜与人物站位/整体走位参考。上传用预演不包含人物细节动作；自然步态、手势、表情和对白表演由完整分镜规定。视频模型只提供参考约束，不能承诺逐帧、像素级或三维一致性。

## 1. 从项目资产接入

读取 [项目与场景接入](references/project-handoff.md)。先查项目索引，再读取用户选定片段的定稿和场景清单，校验模型/素材/分镜哈希、采用版本及状态。用户可以直接说“给第6段做预演”，不要求记住固定话术；歧义无法从索引消除时只确认冲突项。

- 优先消费已有无人 `.blend`，在新的预演版本目录工作，不覆盖资产场景。读取 [本地执行](references/execution.md) 和 [镜头数据](references/scene-contract.md)，使用加载已有模型的模式或项目适配器，不重建已有场景。
- 缺模型、缺关键布局或需要改场景时，明确交给 timeaigc-character-scene-asset-breakdown 的可选空间扩展；传递已有主图/提示词/剧本，不让用户重复整理。未经选择不自动转成资产生成任务。该Skill未安装时说明能力位置并交付缺项，不声称已经调用。
- 本Skill不承担场景美术设计、主图补建及四视图制作。旧版脚本的重建入口只保留兼容历史项目，不是当前默认流程。
- 区分“用户确认”“授权代理自审”“未确认”。实际审查预演后记录依据，不伪造用户看过。已有授权不重复询问。
- 默认交付预演、完整提示词和素材清单供用户自行生成；只有明确要求实际生成或既有授权才提交付费任务。状态未知时查询原任务，不重提。

## 2. 保留分镜结构

原分镜一镜到底就保持一镜到底，不能为降低生成难度改成拼接。时长超过已核实接口上限时保留完整本地预演及提示词，说明生成限制并让用户选择兼容入口；未经明确修改分镜授权不拆段。多镜片段按原切镜点处理，不删对白或以简单测试替代原任务。

只选片段内部分镜头时，记录原始时间范围、局部0秒映射及相邻状态。默认导出所选范围对应的生成材料；若要在整段生成中只约束部分，明确视频覆盖范围，不能假定模型会自动对齐。

## 3. 把分镜转为可播放预演

消费现有 Seedance 2.0、2.5、迷你分镜或打斗分镜的定稿，不重新强制上游所有阶段。保存原文与映射关系：每镜原时间轴、景别、相机、目标点、焦距、人物起终点、持物、视线与连续状态。

- 将自然语言人工解释为镜头数据，不能声称脚本自动理解任意中文分镜。上传用角色代理采用无分节四肢的占位体，仅表达身高、占位、根位移和必要整体朝向；不制作摆臂、迈腿、抬手、点头、呼吸或持物表演。持物手侧、交互与表情写进分镜，不靠代理假动画验证。确需检查复杂接触时另做内部分析版，默认不上传为视频参考。
- 随附标准脚本支持基础体块、相机位置/目标点/焦距线性变化、切镜及角色根位移；不支持骨骼动画、IK、口型、自动运镜规划或碰撞求解。必要扩展写入项目副本并实际渲染验证，不擅自修改安装 Skill。
- 需要手持、曲线穿行、前景遮挡、留白或多人调度时，读取 [复杂镜头预演](references/complex-previs.md)。先定义这些选择要表达的剧情信息，再实现相机路径与整体走位；人物细节表演保留在分镜，不烘焙进上传预演。
- 全片时间从0开始，镜头无缝衔接；JSON时间按预演fps对齐。采用12fps预演时导出24fps只是重复帧，不是新增真实运动精度；快速打斗应提高采样率。
- `scene.blend` 保持无人；每段 `previs.blend` 保存演员和相机。导出干净单画面MP4给模型，编号采样图只用于审查。
- 查看首、中、尾帧和每个切镜前后；预演复核屏幕方向、相机遮挡和角色整体路径，分镜复核持物状态、动作因果与对白预算。持握、细节动作和口型留待生成成片检查，不能为了预演验收重新加入肢体动画。
- 上传前按[验收标准](references/acceptance.md)核对原分镜、实际编码预演的同一时间点。景别名称必须与人物裁切、头顶留白及前后比例对应；延迟揭示检查整个占位体，不能只查头部或稀疏关键帧；指定停稳后检查相机位姿与焦距是否仍被手持/插值改变。发现矛盾先修预演或明确修订分镜，不把所有偏差归咎于视频模型。
- 修改布局或机位后生成新版本，使受影响截图、预演和生成请求失效；不要拿旧参考生成新版分镜。

## 4. 参考生成与实测

编写提示词先读 [视频参考策略](references/generation.md)。默认只用必要人物图、场景图和一条空间预演，不额外添加时间参考图或首末构图图；静态图的时间描述不是硬约束。仅实际生成时读取 [即梦任务执行](references/dreamina.md)。先查看当前CLI帮助确认真实模型、时长、分辨率与输入上限；上游Skill写“Seedance 2.5/30秒”不代表当前API支持。保持分镜版本与实际执行模型两个独立字段。

- 在实际提交的提示词开头逐项声明素材编号、人物名与用途：视频仅参考构图/运镜/站位与整体路径，不模仿占位体姿态、滑动、僵直或动作节拍；场景图提供外观，角色图提供身份与服装。写清代理颜色与真实角色对应，按上传数组核对编号；本地JSON中的role字段不是模型可见说明。
- 先测试能容纳真实动作与对白的短片段，通常约4–6秒；检查成功状态、视频可播放、时长及实际构图/身份/动作后再做更长片段。测试不同时长时选择不同叙事与镜头设计，不只拉长同一镜头。失败分成接口失败、素材失败、生成效果不合格，针对原因做有限重试。
- 生成提示词保留上游完整分镜的标题、时长、影调、角色、场景、逐镜构图、表演、对白与声音，再附参考职责。不能用“按视频运动”替换剧情正文，也不以静默删对白的版本声称完整剧情已验证。
- 多镜片段只有在用户明确同意拆分时才分任务，每段导出相同长度预演并记录衔接；一镜到底未经分镜修改授权不拆。不能把多段拼接说成单次长视频生成。
- 保存请求、素材哈希、任务ID、响应、模型与结果。只在 `gen_status=success` 且已下载检查媒体后报告生成完成；结构保真度另给判断。

## 交付

交付预演MP4、可编辑previs.blend、保留完整分镜内容并增加参考职责的生成提示词、实际素材上传顺序清单、原分镜与时间映射及简短验收。按项目交接规范保存preview-manifest.json并登记索引，绑定具体场景版本与哈希；场景图和空场景只引用已有资产，不重复交付另一套“新场景”。仅授权且生成成功时附真实成片及任务记录。给实际绝对路径链接。

用 [验收标准](references/acceptance.md) 区分“本地可复现”“生成任务成功”“空间与动作质量通过”。保留明确的失败证据及可继续步骤；不要只展示漂亮成片而隐瞒机位漂移。
