## 1. 基线与兼容范围

审查基线来自 `C:/Users/20616/.codex/skills/timeaigc-blender-scene-previs` 的 `SKILL.md`、七份参考文档，以及 `build_scene.py`、`scene_spec.py`、`package_previews.py`、`validate_handoff.py` 和 `dreamina_job.py`。精确文件版本由独立实验目录的源哈希清单绑定，不能用本段路径代替内容指纹。

基线保留的原则：已有无人场景只读接入，预演只参考构图、相机路径、人数、整体朝向和根位移；原分镜的动作、声音及完整对白仍是生成提示词的事实来源。空场景不能被演员污染，空间预演不能宣称验证了步态、表演、持握、精确接触、IK、物理碰撞求解或口型。不能为了验收好看而给代理添加这些动画。

基线的实际实现边界：

- `actor()` 只有身体占位体和头，未实现正面标记或朝向动画。
- `scene_spec.py` 验证 v1 结构，但未知字段不会自动成为功能；不能仅添加 `hands`、`yaw` 或 `dialogue` 字段就声称渲染支持了它们。
- `package_previews.py` 把输入统一编码成 24fps。12fps 输入会重复帧，其他帧率可能重复或丢弃帧，因此升级的帧契约必须显式规定。
- `dreamina_job.py` 原先只要求素材 `role` 非空并检查时长，没有说明版禁止上传、文件用途绑定或清单哈希匹配。
- `validate_handoff.py` 的 `files.video` 只验证引用文件的哈希，并不能证明它是干净版。
- 原碰撞检查仅对盒体做稀疏保守采样，不是连续碰撞或手部接触检测。人物轮廓变大后，应重新检查空间占位，不能沿用旧通过记录。

1.1版本曾将固定四肢作为默认轮廓；该版本保存在旧实验目录的历史快照中。2.1沿用2.0.0的圆柱躯干加头，默认不含手脚、肩臀和分节四肢，前侧浅色贴合条只表示方向。固定四肢转为需明确选择和理由的 `articulated_special`，不能悄悄恢复为默认。任何允许上传的代理仍只改变根位移与整体朝向，子件无动画、驱动、约束或形态键运动；`closeup_static` 始终只供内部诊断。

参考附件的实际像素查看者、物化路径和哈希由主任务记录。父任务已通过受支持物化实际查看原图，确认独立深色窄底栏；本消费端两次本机下载失败，未在本机查看原PNG，不再尝试或猜下载URL。不能声称这些具体人体比例来自附件或当前画面逐像素匹配附件。

## 2. 固定人物资产

### 单一确定性生成器

使用固定 `generator_id`、版本、实际代理模式和共享比例常量。以米计，Z向上，代理底面根节点为原点；局部-Y为正面，局部-X为角色自身右侧。相机屏幕左右与角色左右分别记录。

默认头、圆柱躯干和贴合前条由同一份常量生成；身高统一缩放全部坐标与尺寸。头必须属于实际几何，圆柱底面贴地，不因旧版验收表要求“有脚”而加回肢体。前条用于区分正侧背，不能被描述为衣襟、服装或身份标志，也不加入文字标签或面部表演。

比例是空间占位的工程简化假设，不是医学人体标准或对所有人群的统计拟合。正式报告列出实际总高、头部尺寸、圆柱半径/高度与前条范围。默认代理没有肩宽、骨盆宽或手脚尺寸，不得沿用1.1参数冒充2.0默认结构。特殊分节代理另列自己的比例与用途。

角色身份主要由全身固定颜色区分。同一片段中不同人物使用不同颜色，同一角色跨镜头保持颜色。颜色可读性通过多人实际渲染检查；RGB 数值不同不保证受光、压缩后仍可辨。身高差仅按已确认角色或显式测试输入改变，不加入随机身材、服装、发型或姿态。

确定性证据至少包括：相同输入的归一化几何/材质参数摘要相同，重开 `.blend` 可跳帧复渲染，独立重复运行所选帧相同或报告明确的像素差。`.blend` 二进制整文件哈希可能受保存元数据影响，不能把不同整文件哈希单独当作几何不可复现，也不能省略渲染比对。

### 代理模式与特殊手部

| 层级 | 几何及用途 | 允许结论 | 上传边界 |
| --- | --- | --- | --- |
| 默认圆柱 | 圆柱躯干、头、浅色贴合前条，无分节肩臀手脚 | 构图、机位、站位、整体路径和朝向 | 唯一默认模式；前条仅方向，不能作为服装身份依据 |
| `articulated_special` | 明确选择的固定分节代理，普通轻量手无骨骼 | 特殊构图所需的静态轮廓与占位 | 必须同时具备 `allow_special_proxy:true` 和非空 `special_proxy_reason`；不能自动回退或启用 |
| `closeup_static` 诊断手 | 连续掌体、四指和拇指融合网格；固定指长与左右手约定 | 内部手侧、掌背、裁切、相对尺度和静态连接连续性 | 始终禁止进入干净模型参考，即使填写特殊许可也不例外 |
| 接触/表演研究 | 仅在后续显式任务中实现对应关节、约束、接触目标和测量 | 只报告实际实现并运行过的能力 | 需另立任务范围和验证证据；当前不能声称具备 |

手部特写至少实渲检查掌面、手背、侧面、拇指朝向及五指可辨性，并包含左右手比对；掌指与指节不能呈悬浮珠串，不能存在明显脱节或穿插。可编辑的静态手指不等于 IK，接触点看似贴近不等于求解了持握。当前没有求解器时应直接写“静态构图代理；未验证 IK、接触或手指表演”。

保留 `eyeline_center`、`eye_R`、`eye_L`、`gaze_target` 四个非渲染Empty，单独列入 `locators`。默认位置按身高统一缩放，根节点下局部固定；只供机位定位，没有眼睛网格、自动凝视、约束或子件动画。其命名、位置与非渲染属性都需检查。由分节人物切换为圆柱改变了可见几何，必须实渲新的默认样片，不能复用历史视频假装更新完成。

## 3. 帧与文本数据契约

### 唯一时间轴

推荐将每个片段冻结为整数 `fps` 与 `frame_count`，持续时间严格为 `frame_count / fps`。零基帧 `f` 对应时间 `f / fps`；Blender 帧号为 `f + 1`。每镜使用半开区间 `[start_frame, end_frame)`，所有镜头首尾衔接、恰好覆盖全部帧。切点 `k` 的上一帧属于旧镜，新镜从 `k` 开始。

若保留 v1 秒字段，必须要求 `start * fps`、`end * fps`、`duration * fps` 是整数，转成整数一次后由统一时间表驱动渲染与说明栏。不能分别 `round` 两次后容忍错帧。不得改变原切点、延长片段或插入停格来容纳说明文字。

两个 MP4 都使用同一原生帧率和同一帧数，不默认变为 24fps。若产品需要额外的 24fps 兼容转码，必须作为第三种独立派生品，记录映射，不能悄悄替代两版的基准时间轴。音频不存在时明确标注无声；说明栏展示对白不能作为对白音轨或口型已验证的证据。

### 建议扩展字段

保留场景 v1 的核心字段，并用单独的扩展版本或独立配置声明以下语义；字段名可与最终实现统一，但能力必须真实存在：

| 内容 | 最小信息 | 失败条件 |
| --- | --- | --- |
| 人物资产 | 生成器 ID、版本、实际proxy_mode、参数摘要、坐标约定、手部层级、身份颜色映射 | 未知模式、负尺寸、未授权特殊模式、诊断手进入clean或记录与输入不符 |
| 时间轴 | fps、frame_count、每镜整数起止帧、源分镜时间映射 | 重叠、空洞、零帧镜头、越界或非整帧切点 |
| 每镜文字 | 简要说明与原对白分开；对白含说话人、原文，允许空列表 | 将动作说明拼入对白、丢词、用摘要替换台词 |
| 文本分页 | 每页帧区间及原文连续字符范围 | 字符缺失、重复、页时间重叠、超出所属镜头 |
| 输出用途 | model-reference / review-only / diagnostic-only | 未知用途、同一路径被赋予冲突用途 |
| 文件证据 | 相对路径、SHA-256、尺寸、fps、帧数、来源帧序列摘要 | 指纹不符、输出缺失、无法完整解码 |

未知扩展字段建议在新校验器中拒绝或明确警告为未实现，避免“输入接受成功”被误读为功能完成。旧数据兼容路径应显式选择并保留原能力说明。

### 中文说明栏

从已经渲染的干净帧复制整幅图像，在其下方新增独立画布；不重新渲染场景，不缩放、覆盖、裁切或挪动原画面。输出宽度保持 W，顶部恰好为原 H 像素；说明栏高度固定为整个片段统一值，最终高度满足编码器偶数要求。

每镜简述与对白分区显示。空白或空对白显示单独一行“（无对白）”，不能添加台词；该标签仅属于说明版。使用可验证的中文字体，按实际字形宽度换行，检查字体覆盖和边界，不按英文空格或固定字符数推测。中英文混排、数字、全角标点、源换行都要测试。

2.1默认 `compact`、`--panel-height auto`，按真实文字排版和阅读预算选择满足全片的最小固定栏高，不沿用216px或128px硬下限。简述每页完整重复，最多两小字号行，超出时明确建议expanded；长对白可分更多页，页面源切片必须逐字还原原文（包括换行、空白和标点）。固定高度不会随镜头上下跳动；只允许为编码偶数尺寸补至多1px。渲染换行不改变源串，保存每页字符范围与展示帧范围；不截断、不加省略号、不缩小原画面。

默认画面不含用途警示，也不重复“说明/对白”标签。可选 `--show-usage-hint` 只允许一句“预览视频仅供观看/上传生成请用干净版”，其占用需计入排版。短描述无对白的独立S10用例检查自动栏高和留白；不能仅在长对白样片上观察后就宣称所有短文本都紧凑。`review-only`和生成白名单始终保留，不依赖可见提示。

默认阅读门槛是每个非静默页至少2秒、每秒最多6个非空白Unicode对白字符（含说话人标记和标点，不含重复简述）；允许显式配置。页面在原镜头整数帧区间内安排，不改变切点或时长。空对白单页静默，不套用对白的2秒门槛。无法在空间上限及时间预算内排下时明确失败并建议显式 `--mode expanded`，不能自动改变模式、延时或插入停格。展开模式按全文最大高度统一加栏，是可选全文对照，不能解决原镜头阅读时间不足；限制记入报告，不绘制警示文案。

“完整显示”与“足够时间读完”分开验收。短镜头放满长台词可以满足字符覆盖，但仍可能阅读失败；报告须同时给出每页字符数和显示时间。测试不能只检查生成的文本 JSON，还要查看实际像素确认无方框字、裁切或越界。

## 4. 两版一致性与防误用

### 比对层级

1. PNG 级：每个说明帧顶部 `(0, 0, W, H)` 与对应干净帧逐像素相同，所有帧通过才能写“合成没有改动原画面”。
2. 时间级：两个最终 MP4 完整解码；尺寸、帧数、fps、起始时间、每帧 PTS 与时长一致（允许容器时间基的明确量化误差）；最后有效帧必须存在。说明页与切点从同一整数时间表派生。
3. 编码级：独立 H.264 有损编码会使顶部像素有差异，不能写“解码逐像素相同”。如使用兼容的无损像素格式和编码配置，应对实际解码后的顶部裁剪逐帧比对或计算帧摘要，再据实报告。若保留有损交付，则报告预先设定的差异阈值和最大/平均差异，严格区分源帧相同与成片编码差异。
4. 人眼级：实际查看两个成片的首、中、末帧及每个切点 `k-1 / k / k+1`，同时查看长对白分页切换与静默镜头。数值相同不能代替文字可读性审查。

### 防误用应落实到入口

清单只将干净版列为模型视频参考。紧凑与展开观看版的文件名、`review-only`用途元数据和底部说明栏都明确面向人类审查；内部手部分析资产再用独立角色。不要仅靠文件名判断，也不要扫描目录自动上传所有 MP4。复用原干净字节时保留原输出与原引用，另建观看版目录并重新验证新说明MP4；不能为了分页重编码或覆盖原干净交付。

v1项目交接可保留 `files.video` 指向干净版；当前v2参考清单使用 `files.clean_video`、`files.review_video`，不能混用两个schema。生成请求必须要求用途 `model-reference`、哈希与清单一致、文件位于上传白名单、完整 `proxy_reference` 重算通过；受控渲染和人工抽查负责确认无注释区。显式拒绝 `review-only`、`diagnostic-only`、未知用途、缺失/过期绑定、指纹变化和说明版冒名。用途字段可伪填，必须与源spec、实际演员记录、clean视频、全文提示词和覆盖报告绑定，不能只相信标签。

本次不运行付费生成。防误用测试应在本地准备阶段通过桩数据或纯验证函数完成，不能为了测试拒绝逻辑调用付费提交。准备失败必须发生在任何外部命令或上传之前；报告该测试验证的是本地保护，没有证明服务端识别能力。

| VID-01 | 对所有说明 PNG 裁取顶部比较 | 全帧逐像素相同；说明区坐标不侵入原画幅 |
| VID-02 | 全量解码两版 MP4，核对 PTS 与画面 | 帧数/时长/fps 一致；记录编码方式与真实顶部误差；首末帧都存在 |
| CLEAN-01 | 检查干净渲染对象和打包路径，并抽查成片 | 无渲染文字对象、编号、字幕、底栏；干净编码只读取干净帧目录 |
| SAFE-01 | 正常干净引用准备；compact/expanded说明版、分析版、改名版、哈希变化分别尝试准备 | 只有白名单干净内容通过；拒绝发生在上传或外部 CLI 之前 |
| PROMPT-01 | 实际代理模式、身份颜色映射与全文输入 | 提示词准确声明模式/颜色映射，完整保留storyboard_text及每镜source_text/dialogue；摘要不能代替全文；提示词哈希与clean/源输入/渲染记录绑定 |
| REUSE-01 | 新目录使用已验证输出的干净视频 | 原MP4字节/哈希、原目录与原引用保持；新说明版完整解码/PTS/分页/切镜验证 |
| SAVE-01 | 独立 Blender 进程打开保存文件，跳到复杂中间帧和切点后帧重新渲染 | 相机、角色、颜色与交付帧一致；不是依赖初次运行内存状态 |
| COMPAT-01 | 原版 `assets/example-scene.json` 以明确兼容模式读取 | 旧数据可处理或收到清晰迁移错误；未知字段不伪称实现 |
| ERR-01 | 重复 ID、非法颜色/尺寸、时间空洞、非整帧切点、输出非空 | 拒绝并保留原文件，不能覆盖已有验证输出 |

自动检查和实际审片应互补：字体覆盖表不能证明排版好看，PNG 比对不能证明 MP4 完整，首中尾抽样不能证明所有帧无多余文字。干净输出最好由受控的无文字渲染路径结构性保证，再用最终成片抽查；没有可靠 OCR 或逐帧文字检测时，不把 OCR 未检出当作无文字证明。

## 6. 交付与报告措辞
