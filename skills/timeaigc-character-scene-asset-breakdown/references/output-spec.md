# 输出与绘图提示词规范

本文件完整适用于默认常规路径，角色部分保持不变。用户选择主图后的三维场景扩展时，补充视角及资产包交付改按 [spatial-scene.md](spatial-scene.md) 执行；不强制重跑本文件的整套角色/场景拆解，也不要求三张单视角编辑提示词伪装成一次网格生成。

## 四、中文与 MJ 英文提示词

只有全局画风确定后才写最终提示词。每条中文提示词下紧接单独一行 `**MJ 英文提示词：**`，英文正文保持为一个连续段落。用户明确只要某种语言时从其要求。

### 角色两部分提示词

**第一部分：头部近景。** 构图范围为肩颈以上，完整呈现头顶、发型轮廓、脸部及颈部，以头部脸部为主体；不出现腰腿或全身。按画风、身份年龄、正面近景、中性表情、脸型骨相、肤色与皮肤质感、眉眼鼻唇、耳部、发际线发型和辨识特征、背景光线组织。保持单人、正视镜头、高级灰背景、柔和影棚光，默认 3:4；衣服只描述画内领口等可见部分。

**第二部分：参考近景生成全身立绘。** 明确“以『角色名·头部近景·实际基础状态名』图为参考”，保留该图的身份、脸型五官、肤色、发型发色、年龄感和画风，将构图扩展为正面全身。补全体型、服装层次与材质颜色、鞋履、配件道具和自然站姿；这些内容来自剧本及允许的保守推断，不声称可从近景中看到。不要同时要求保留近景裁切和展示全身。

以下顺序和全身约束仅用于第二部分：

按画风 → 单人身份与年龄 → 正面全身及中性站姿 → 面部辨识 → 头发与体型 → 衣物鞋履 → 配件道具 → 背景光线 → 画幅组织。

保留正视镜头、脚部完整、干净高级灰背景、柔和影棚光、无其他人物和无复杂场景。双手默认自然放松；必须持道具时改为安全静态持法，不同时要求持道具和双手空放。道具不遮挡核心身体轮廓。

### 场景两部分提示词

**第一部分：单视角主图。** 优先纳入剧情必须展示的主要区域、出入口、关键道具和相互位置，尽可能多地覆盖主要内容；不能把关键内容推迟到第二部分。先保证空间可读性和合理透视，再把主图难以容纳的次要、不重要区域留给网格补全。

按画风与无人场景 → 时间地点 → 能呈现主要区域关系的视角 → 地面材质 → 光影 → 前景 → 中景 → 背景 → 顶部或天空与氛围 → 无人物限制与画幅组织。

每条只描述一个完整画面和一个可执行视角，例如根据空间选择正面或斜侧中的一种，不同时并列多个观察方向。直接描述所需画面，不加入网格、分屏或视图拼接指令，也不把这些内容扩写成冗长的负面提示词。

现实、回忆、昼夜或破坏前后存在必要视觉差异时，分别写为该基础场景下面的状态修改条目；没有视觉差异就不新增状态。每张结果只呈现一个目标状态。

**第二部分：参考主图生成 2x2 网格场景图。** 明确以“场景名·单视角主图·实际基础状态名”图为参考，生成一张 2x2 网格图，整体默认 16:9。保持同一地点、时刻、陈设状态、建筑材质、光源逻辑与画风；不要要求所有格子与主图观察角度相同。

以主图可识别的门窗、墙面、家具或地标建立固定空间坐标。按左上、右上、左下、右下逐格描述主图外或被遮挡区域的细节、机位朝向、范围及与已知区域的连接关系；优先分配不同次要区域，不机械套用顶视／正面／左右四视图，也不把主图简单复制四次。镜头变化后用固定地标说明位置，避免把画面左右当作恒定空间方位。

原文支持的主要结构不得改动；不可见区域无法从图片唯一恢复，新增细节仅作有依据的保守补全，影响空间结构的关键未知需确认。四格不得出现互相矛盾的门窗、通道、家具数量或位置。全部使用“无人场景”表述，英文使用 unoccupied scene，并保持无人群、人影、人体剪影和尸体的限制。

### 状态修改提示词（角色与场景通用）

每条采用“输入图 → 保留内容 → 允许变化的对象与范围 → 修改后的完整目标状态 → 必要资产约束”的顺序，以自然语言表达，不拆成繁琐字段表。

- 输入明确写为“以『角色名·全身立绘·实际基础状态名』图为输入”或“以『场景名·单视角主图·实际基础状态名』图为输入”。若基础状态另有名称，使用实际名称，保证用户能唯一定位。
- 多个状态默认分别从基础图派生，不隐含串行编辑关系。用户不需要先生成状态一才能生成状态二。
- 从基础图生成后期状态时，写出全部累计变化。例如基础图没有伤势，后期状态既有左臂旧伤又有额头新伤，应同时描述两处伤势，不能只写额头新伤。
- 确需使用某个已有状态图时，直接指定该状态图名称，并根据该输入写变化；不使用“参考上一张”等模糊指代。
- 场景保留无需变化的布局、视角、建筑、门窗、家具和画风；夜景修改光线，家具移动允许指定家具位置改变，坍塌允许指定结构破坏。不得一边要求所有结构完全不变，一边要求建筑坍塌。
- 默认场景状态修改以单视角主图为输入，保留其单画面构图和观察视角，形成一张目标状态图。一致性指基础图与状态图之间的连续性，不要求在同一张图内同时展示多个状态或视角，也不保证编辑效果必然一致。
- 角色保留身份辨识、画风、构图和未受影响的外观配件；换装允许指定服装变化，年龄或变身允许对应五官、体型改变，保留仍适用的辨识特征。不使用与目标变化冲突的全局“不变”指令。
- 默认角色状态图参考全身立绘并保持正面全身、中性静态、完整脚部；若明确修改头部近景，则保留近景范围。场景状态图默认参考单视角主图并继续无人；若指定网格图为输入，则保留四格对应关系与各格视角，同步目标状态。仅在用户明确要求扩展资产时改变该模式。
- 保留必要约束即可，不重述整套基础图描述。每条修改提示词后紧接 MJ 英文修改提示词，二者对应相同输入和编辑目标。

### MJ V8.2 适配与长度

英文从视觉基线压缩生成，不机械翻译。保留画风、身份与外观辨识、数量、服装颜色、构图和空间方向；去除人物关系、证据、时间统计及重复修饰。基础提示词使用生成描述，状态英文保留输入图、保留范围和修改目标，不能改写成重新生成整个对象的独立描述。

场景第一部分中英文均采用单画面、单一视角；第二部分均明确参考输入图和 2x2 网格，逐格对应相同区域、方向、细节与位置关系。角色第二部分英文也必须引用头部近景并表达扩展为全身，不能退化为独立文生图描述。

- 角色近景英文正文目标 60–100 词，复杂基础场景目标 80–140 词；参考图生成全身和网格的英文以完整表达参考依赖、补全细节及空间关系为准；状态修改以完整表达必要差异为准，可更短，不重复基础特征凑字数。
- 这是提示词编写预算，不是 MJ 官方限制；超出目标先压缩冗余，必要关键细节不截断。
- 正文按空白分隔计词，参数另算；单词、字符、token 不混称。需要报数时实际统计，不能估猜。
- 生成可直接提交的 MJ 行前，核实目标入口及 V8.2 参数兼容性；优先查官方版本和参数文档，同次任务复用已核实结论。
- MJ 尾缀使用连续两个 ASCII 短横线 `--`；正文与尾缀之间、参数名与值之间各留一个空格。参数集中在英文段落末尾，参数后不追加正文、备注或句号；比例使用半角冒号。禁止 `—ar`、`- -ar`、`--ar: 3:4`、`--ar 3：4` 等写法。
- 默认 V8.2 首次生成：角色近景尾缀为 `--ar 3:4 --v 8.2`，场景主图为 `--ar 16:9 --v 8.2`。用户指定其他兼容版本或画幅时相应替换，不叠加冲突参数。
- 参考图生成的目标画幅必须显式设置：角色全身使用 `--ar 9:16`，场景网格整体使用 `--ar 16:9`，避免继承近景的 3:4。头部近景状态使用 `--ar 3:4`；其他状态使用其目标图画幅。
- 未指定入口时按 MJ 网页 Imagine Bar 附图方式交付，正文末尾放目标 `--ar`，在正文外说明把指定参考图添加到 Attach to prompt，并选择兼容的 V8.2 Edit 模型。不要把本地资产名称当作已上传图片。
- 用户使用 Discord 时，参考图尾缀需增加 `--edit` 及真实可访问的图片 URL，例如参数结构为 `--ar 9:16 --v 8.2 --edit` 后接真实 URL。尚未获得图片 URL 时，不虚构链接、不输出含占位符的“可直接提交”指令；先交付正文与画幅，并在正文外注明上传图片后需补齐 `--edit` 图片链接。
- 以上语法依据 2026-09-15 官方参数与 Edit 文档；入口或版本变化时重新核实。不要擅自追加 `--raw`、`--s`、`--q` 等用户未要求的设置，不把“2K”“生成 5 张”等文字视为有效参数。
- 第二部分参考图生成及状态修改使用目标平台相应的参考图或图像编辑入口，按该入口核实模型与参数兼容性，不机械追加文生图版本或画幅参数；无法核实时提供英文编辑正文和一句必要的入口说明，不宣称特定编辑模型支持已验证。
- 如果入口给出硬限制，按其明确单位检查完整输入，不能用内部词数预算代替；若必要内容与硬限制冲突，说明缺口并提供可执行的精简版。
- 未查到官方长度上限时，说明尚未核实硬上限，不宣称无限制或已保证符合某个官方数值。无法核实参数时仍可输出英文正文，参数使用平台界面设置，并在参数说明中标注待核实。

官方核实入口：[参数列表](https://docs.midjourney.com/hc/en-us/articles/32859204029709-Parameter-List)、[Edit 模型](https://docs.midjourney.com/hc/en-us/articles/48495453462797-Edit-Model)、[版本说明](https://docs.midjourney.com/hc/en-us/articles/32199405667853-Version)、[提示词指南](https://docs.midjourney.com/docs/prompts)。

## 五、交付结构

### Markdown 文件交付

默认实际保存本次生成内容为 UTF-8 `.md` 文件，不仅在聊天中展示或声称已保存。用户明确要求仅聊天输出时遵循其要求。

- 优先使用用户指定输出路径；未指定时放在输入剧本所在目录，无输入文件时放在当前工作目录，文件名用“作品名_角色场景资产拆解.md”。缺少作品名时使用“角色场景资产拆解.md”。
- 写入前检查同名文件。用户明确要求更新既有结果时只更新授权部分；否则添加时间戳避免覆盖。不要把生成结果放进 Skill 文件夹。
- 将全局画风、角色与场景两部分双语提示词、必要状态修改及使用说明完整写入文件。定向和增量任务只保存该次授权内容。
- 保存后用 UTF-8 回读，确认正文完整、中文正常，运行校验脚本并修复错误。最终回复提供文件绝对路径链接，简述完成内容。
- 风格未确定时可保存“作品名_资产拆解_待确认.md”，只包含当前可交付内容及待确认方向，不伪造最终提示词。写入失败或环境无文件能力时明确说明，保留完整可复制正文，不声称已保存。

### 最终回复与下一步选择

完成含场景的常规资产拆解后，在最终回复的文件链接及必要验证说明之后，必须直接向用户提出一次可选三维阶段的选择；这属于交付衔接，不是需要隐藏的制作清单。不能仅在资产文档、项目索引或内部计划里记录，也不能用“未自动生图或建模”代替。

可按实际范围使用以下表达：“第一阶段资产提示词已完成。接下来是否要选一些场景，继续制作三维空场景并补齐四视图？可以先停在这里；要继续时，先生成选定场景的主图，再把主图发来即可。我会结合已保存的提示词和剧本继续。”

主图尚未生成时也要提供该选择，不要求用户现在就上传。用户仅说“先完成常规拆解”“不自动建模”，仍要询问下一步，但不得据此启动建模或外部生成。用户明确要求不提供后续建议、已拒绝该扩展、此次仅处理角色，或已明确选择下一阶段时，不重复询问；已选择时按已有选择及所缺输入衔接。将这里的“第一阶段”明确指向资产提示词阶段，不与下游分镜 Skill 的阶段编号混用。

### 内容排版

默认只展示全局画风、角色、场景。采用对象名称标题、基础与状态小标题、连续提示词段落；不用管理表格，不重复输出独立档案和提示词库。定向模式删除不适用部分，增量模式只展示本次变化内容。

同一对象按第一部分、第二部分各输出一次，相关状态紧接其后；没有其他状态就只给两部分基础提示词，不添加“无其他状态”等空字段。基础名称应能表达实际所选状态，避免让用户误认基准图内容。

排版示意（正式结果填入实际内容，不保留以下占位文本）：

```text
全局画风：确定的画风及必要来源说明

MJ 英文提示词：对应英文近景生成描述。

第二部分：全身立绘·实际基础状态名
参考图生成提示词：以该角色指定头部近景图为参考，保持脸部身份特征，补全服装体型及鞋履，生成正面全身立绘。
MJ 英文提示词：对应英文参考图生成指令。
```

必要的尺寸、输入图、关键推断或平台说明放在相关条目附近，用短句说明；共同的平台说明全篇写一次即可，不在每条提示词下重复。不把来源、依据或使用备注混入可复制正文。

默认不展示制作清单、资产与候选数量汇总、整理场次、出场定位、时间统计、优先级、复用调整分类、暂不单独生成列表、排除理由或中间分析过程。用户明确要求时间统计、完整视觉档案或制作分析时，再按指定范围提供；不因一个额外字段请求自动恢复整套复杂输出。

缺少画风时遵循风格待确认模式。关键未知与重大设定冲突仍需简短说明或确认，不能为了简洁而伪造结论。
