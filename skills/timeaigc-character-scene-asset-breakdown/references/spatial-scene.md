# 可选：从主图制作可复用三维场景

## 进入条件与已有上下文

常规路径继续按 [输出规范](output-spec.md) 交付原来的两部分提示词；不等待主图、不自动建模、不自动生图。最终回复必须按其中“最终回复与下一步选择”询问是否进入本扩展，不能只在项目索引里记录。用户未选择时，本次常规任务已经完成，不自动启动扩展。

用户选择该扩展，或在已有约定中发来主图要求继续时，读取项目索引、该场景原提示词、剧本场次及已确认设定，实际查看主图。不要重新索取项目里已经存在的信息。仅发图片且意图不明时，先匹配场景并确认用途；图片不自动授权建模或付费出图。无文件访问能力或上下文记录缺失时，只索取必要缺项，不假装记得其他对话。

角色流程不变。此扩展只制作无人场景，不拆动态镜头，不替代下游分镜或动态预演。

## 从主图到平面图

1. 保存原图和原提示词，建立稳定场景ID、状态及版本，按 [项目资产交接](project-handoff.md) 管理文件。
2. 对照剧本，列明主图可观察的出入口、物件顺序、可通行区域与需要容纳的表演。只用短说明标出影响空间的未知。
3. 写同一份米制、Z向上的 scene-spec.json，再生成无人俯视结构图；不是让图像模型自由猜一张漂亮平面图。区分原文、图片观察、推定尺寸及不可见区域的设计补全。
4. 先解决影响剧情的门窗、通道和隐藏区域；按已有授权确认或代理自审并记依据。单图或AI生成360全景均不能唯一恢复真实尺寸；全景只能辅助空间线索，存在接缝或结构矛盾时不照单全收。
5. 可见结构与主图优先对应。主图透视无法由一致三维空间实现时说明具体矛盾，给出最小修正方案，不偷偷重绘主图或以“精确重建”交付。

## 空场景与四个对应机位

读取 [静态场景数据与执行](scene-build.md)，生成可编辑无人 scene.blend，保留“主图匹配＋鸟瞰＋反打＋侧面”的四视图逻辑：V01匹配原主图，V02为鸟瞰斜俯视（约45°，不强求精确角度），V03为主图反打，V04为关键侧面。在此框架内调整各机位的位置、高度、朝向和适度焦段，使四图合起来尽量完整覆盖水平360°，并保留相邻图的共同地标；不因补盲区默认取消鸟瞰或替换视图类型。鸟瞰兼顾整体布局与其余视图未充分展示的区域，反打和侧面补足主图背后及两侧。

### 焦段、覆盖与相邻视图

- 补充机位以36毫米传感器宽、约28–35毫米焦距作为试拍起点，按实际空间适度调整，不一律改成长焦。狭小空间可酌情使用24–28毫米；低于24毫米不作为收全场景的默认办法，须说明必要性并检查近大远小和边缘拉伸。V01优先匹配已确认主图，不为统一焦段破坏对应关系。
- 同时调整相机位置、朝向和近处物件距离。仅在原地加长焦距只会缩窄取景，不能消除原机位造成的夸张远近比例。避免镜头紧贴家具；在真实可通行空间内退后或移位，让四图分担覆盖，不靠扩大房间、缩小家具、穿墙或删墙解决取景。检查镜台、床柱等前景是否过大，以及远处表演区域是否显得过远；不把空间参考图的广角构图强加给后续近景镜头。
- 四张图合起来尽量完整呈现场景水平360°的环境内容：四周墙面或边界、转角、出入口、关键陈设和剧情通路。结合平面图逐区域核对实际渲染的可见范围与遮挡；四个相机朝向不同、或视场角相加达到360°，均不能代替覆盖检查。无需保证每个物件背面、柜内等不可见表面全部入画。
- 按空间相邻关系组织四图，使相邻图尽量共有1–2个清晰可辨的固定地标，如同一门框、床柱、窗或家具及其邻近结构，形成可串联的重叠关系。不能只凭相同材质或重复花纹认定重叠；共有地标要能辨识，但不要因此让多张图重复同一大片区域。
- 在已有场景档案的审查记录中简记每张图覆盖的区域、与相邻图的共有地标及剩余盲区。先在四张内通过重新分配机位解决缺口；空间复杂、遮挡或原主图限制导致仍无法兼顾时，如实标明缺口并提出最小调整，不自动增加交付参考图，也不宣称已完整覆盖。

四张简模图都来自同一场景，包含匹配主图的V01。记录相机位置、目标、焦距、画幅、坐标和匹配误差。核对人物预期尺度、相机距离与通道宽度，不能只凭“广角/中景”等名称判断空间。无人基础模型不放人形代理，不为取景静默删墙；剖切审查图另存，不能冒充正常机位。

既有 .blend 先复制检查，不交给会清空环境的重建脚本；必要适配写在项目内。几何、平面图、机位图必须一致，输出完整可供下游调度的场景，而非只有主图可见的一片布景；不可见区域仍明确为设计补全。

## 单个视图修改与用户接管

用户提出某个视图的角度、构图或焦段修改时，执行以下顺序：

1. 根据视图编号或图片定位对应camera_id；只在确实无法判断时询问。保存新版本或工作副本，保留原模型和已接受图片，优先只调整指定摄影机，不顺带改变场景几何和其他机位。
2. 先渲染并展示该机位的新简模图，简述改动；必要时并排展示修改前后。复核水平四周覆盖及与相邻图的共同地标，发现缺口先说明。此时明确等待用户确认角度，不调用成品图生成服务；之前的一般出图授权不替代本轮角度确认。
3. 用户继续提出意见时，仅迭代简模。收到明确认可后，再沿用已有出图授权生成该视图的成品；用户自行出图时，交付确认后的简模及更新提示词。只更新受影响的单图、拼图、相机参数与版本清单。旧成品仍可作历史对照，但不能作为新机位的已完成成品。
4. V01始终优先匹配原主图；若修改意见会使V01不再匹配，先说明差异并确认是恢复匹配还是更换主图。仅批准简模角度，不自动授权替换原主图。

用户要求在Blender中亲自调整时，立即转入人工接管，不要求先经历固定次数的失败：

- 读取该场景版本及camera_id，用Blender可见窗口打开可编辑工作副本，切到该摄影机的取景视角并选中摄影机；让用户直接调整位置、旋转或焦距。具体操作见 [静态场景数据与执行](scene-build.md) 的人工机位接管部分。不能只打开文件而停在默认自由视角，也不能打开新建的空场景。
- 告知正在编辑的视图和保存位置，等待用户调整、保存并通知完成；期间不后台改写该文件，不从旧scene-spec重建覆盖用户改动。已有Blender会话存在未保存修改时，保留该会话，不强制关闭或切换文件。
- 用户完成后，以保存的blend内实际相机为准读取位置、旋转、焦距、传感器、偏移、画幅及相关约束，按实际取景同步场景数据；含约束或自定义相机设置时保留blend，不把它简化为有损重建。渲染该机位简模供用户确认；若用户已明确认可该实际取景，不重复索取同一确认。成品生成前仍须有对应机位的明确认可。
- 将待确认视图、简模路径、工作副本路径和确认依据记录到已有场景档案，便于跨对话继续；未确认草稿不替换项目的已采用版本。无法实际打开或验证摄像机视角时如实说明当前状态，提供文件与切换方法，不声称已就绪。

## 成品四视图：原主图加三个补角度

- 成品V01保留用户主图的原文件，不重新生成；尺寸不同时只在拼图中等比适配，不覆盖单图。简模V01是对应机位截图，不混进成品拼图。
- V02–V04逐张处理：对应简模截图提供几何和机位，原主图提供风格、材质与光源逻辑。默认不追加更多参考图；只有当前视角确有缺失且用户需要时才补充，并说明职责。
- 每张提供完整提示词及上传顺序，例如：“图1为本机位简模，保持投影、门窗及物件位置；图2为原主图，只提供美术与光照，不覆盖本机位。输出单张无人画面。”保留实际场景设定，不用该骨架代替具体内容。
- 用户自行出图：交付三张简模图、三条对应提示词及参考说明，状态记 appearance_pending，不能声称已交付真实成品四视图。用户回传后检查再归档。
- 用户要求代为出图：使用可用图像编辑能力逐张生成并检查；处于角度修改流程时，先完成上述简模确认再生成。主图可来自MJ；补角度选择实际支持主图和简模参考的工具，不将几何参考能力写成MJ的既定能力。保留原英文/MJ常规提示词，不把多图编辑指令强行改写为不兼容的MJ参数。
- 检查数量、连接关系、共同地标、遮挡、光线、无人及机位是否重复；对照简模复查四周覆盖和相邻图的重叠地标，不能让补图擅自放大前景或改变远近关系。仅修正失败单张，不因一次失败自动批量付费重抽。没有生成授权则交付材料，既有授权不重复询问。

## 交付与交接

交付无人平面图、scene-spec.json、scene.blend、场景档案、两套同编号/同排列的四视图和各自单图、补图提示词与参考说明。成品四视图为主图+三个补充角度；简模四视图为主图匹配机位+三个对应机位。真实图尚未完成时明确缺项，不用灰模/占位图顶替。

使用 project-handoff.md 的场景清单区分 geometry_status、appearance_status 和审查依据。几何已可用而补图未完成时，允许先做本地动态预演；不把“可预演”误写为场景图全部完成。布局、主图或状态修改后创建新版本，复查受影响机位；未改角色及其他场景不重做。
