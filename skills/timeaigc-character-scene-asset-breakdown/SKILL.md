# TimeAIGC_角色&场景资产拆解

本技能以角色、场景及其必要状态为单位建立可复用的静态视觉资产。目标是在保留关键剧情资产与连续性的前提下，减少不必要的独立出图项。

## 核心原则

- 忠实提取原文，不新增剧情、关系、能力或改变设定的内容。
- 分析时区分“原文明确”“合理推断”“信息缺失”。影响使用的关键推断以简短说明标注 `（推断：依据）`，不放入可复制提示词；依据不足时保留未知，不将推断伪装成原文。
- 先建立实体并判断复用，再决定独立出图项，最后编写提示词。记录变化不等于单独生成。
- 在分析中判断新增对象或状态是否必要，不向用户逐项展示筛选过程。不得为了降低数量遗漏关键资产，也不设置机械的资产数量上限。
- 同一对象集中展示一次：先给两部分基础资产提示词，再给必要状态的图像修改提示词。状态修改依赖指定基础图，不重复写成独立文生图提示词。
- 沿用用户指定画风，保持媒介、时代、地域、材质一致。
- 角色第一部分为肩颈以上近景，突出头部脸部细节；第二部分参考该近景图生成单人、正面全身、中性无明显情绪、静态站立、脚部完整的立绘。表情组、动态姿势、转面图仅在用户要求时作为扩展资产。
- 场景图为无人场景，不出现人物、人群、人影、人体剪影或尸体；不得用雕像般站立的角色规避限制。确有必要的非人形建筑雕塑须明确材质。
- 场景第一部分为单张、单画面、单一观察视角的主图，尽可能覆盖主要剧情区域和关键陈设；第二部分参考主图生成 2x2 网格场景图，重点补全主图外的次要区域及其位置关系。中英文遵循相同构图要求。
- 默认交付全局画风、角色和场景提示词，不展示制作清单及中间分类。用户同时要求实际出图时，将完成的规范交给可用图像生成能力，不声称已经生成图片。

## 工作模式与输入

提取剧本、处理范围、目标画风、时代地域、已有资产 ID、目标片长、场次或时间轴、目标绘图平台及用户禁用项。没有剧本或等价故事信息时，索取内容，不虚构拆解结果。

- **完整拆解**：完成资产分析，按“全局画风 → 角色 → 场景”交付各对象的两部分基础提示词与必要状态修改提示词；分析和档案不默认展开。
- **定向拆解**：只处理指定角色、场景或章节；开头注明范围。
- **增量更新**：沿用既有名称和 ID，只输出受影响对象的基础或状态修改提示词，必要时一句说明影响；不默认列变化清单或保持不变项。不因出场顺序变化重编号。
- **风格待确认**：用户未给画风且未授权代定时，先完成可做的资产分析，简短提供 2–3 个画风方向后等待选择；不展开制作清单或输出占位提示词。
- **授权代定风格**：用户说“你来定”“直接做”等时，自行选择统一画风并标注推断依据，完成全部输出。

非关键参数缺失不阻塞工作：角色第一部分近景默认 3:4，第二部分全身立绘默认 9:16，场景主图及网格整体画布默认 16:9；2K 可列为交付目标，不等同于平台已支持或保证的生成分辨率。出图数量和视图形式按下文决定。

设定冲突依次采用用户当前明确说明、较新且具体的设定、与剧情连续性一致的描述；仍有多个重大解释时列出冲突并请求决定，继续处理不受影响部分。

## 读取参考与执行顺序

1. 开始资产分析前，读取 [references/asset-rules.md](references/asset-rules.md)，完成实体归并、基础与状态选择、连续性和视觉基线；默认不展开分析过程。
2. 准备提示词及交付前，读取 [references/output-spec.md](references/output-spec.md)，按对象输出基础生成与状态修改的中英文提示词。
3. 默认将本次完整交付实际写入 UTF-8 Markdown 文件，按输出规范确定路径；写入后回读并运行 `python scripts/validate_art_direction.py <文件路径> --mode full`；定向输出用 `--mode character` 或 `--mode scene`，增量及提示词片段用 `--mode prompts`。用户只要求中文时加 `--language zh`，仅英文时加 `--language en`；标准第二部分网格提示词使用 `网格场景提示词` 标签，自动允许多视角；用户另行要求其他多视角扩展时加 `--allow-multiview`。
4. 修复 `ERROR`，结合用户实际要求复核 `WARNING`。脚本仅检查可识别提示词块及常见遗留问题，不能判断剧情漏项、身份一致性、空间合理性或实际编辑效果；仍执行下列人工复核。

## 六、交付前复核

- 同一连续空间、同一角色是否正确归并；新增对象、状态与补图是否有实际用途。
- 现实／回忆标签、轻微战损或不同景别是否被误当成新增实体。
- 核心短暂资产和必要状态是否保留，选中项是否能追溯到原文。
- 每条修改提示词是否指向确切的基础或状态图；既有名称与 ID 是否稳定。
- 用户要求时间统计时，时间码是否有依据、估算是否标注、重叠是否避免重复累计。
- 事实、推断、未知是否区分；脸部、服装、伤势、布局和陈设是否能连续保持。
- 角色是否先近景再参考近景生成全身；场景是否先单视角主图再参考主图生成 2x2 网格，全部场景是否无人。
- 第一部分中英文场景主图是否保持单视角并覆盖主要内容；第二部分是否写清四格各自的区域、观察方向和相对主图的位置，避免重复主图或布局矛盾。
- 中英文关键特征、颜色、数量、左右关系与画幅是否一致；英文预算是否被误称为官方上限。
- 第二部分是否明确引用第一部分图像，两部分是否都有中文与 MJ 英文；每个对象是否先两部分基础、后状态；是否把状态修改误写成另一套独立文生图提示词。
- 保留要求是否与允许变化冲突，后期状态是否包含从输入图出发所需的全部累计变化。
- 默认结果是否清除了制作清单、场次定位、优先级与排除项，是否存在重复档案或空字段。
- 是否残留占位符、互斥指令或“同上”；是否错误声称已经生成或验证图片。
- Markdown 文件是否已实际写入、回读并校验，最终回复是否提供可访问的文件链接；近景是否为 3:4，MJ 尾缀是否符合目标入口语法。

按以上规则复核交付内容。实际生成效果、英文预算与复用成本需通过用户剧本和图像结果继续验证。
