# TimeAIGC_角色&场景资产拆解

## 核心原则

- 忠实提取原文事实，不新增剧情、关系、能力或会改变设定的内容。
- 区分“原文明确”“合理推断”和“信息缺失”。每项推断写成 `（推断：依据）`；依据不足时保留未知并列出缺口，不把猜测写成事实。
- 把角色、服装、道具、年龄、伤势、场景时段和破坏状态整理成可复用的资产基线。需要独立出图的变化建立变体，不用互相冲突的描述拼成一个资产。
- 先统一全局画风，再写单项提示词。沿用用户提供的画风原文，不擅自混入不兼容的媒介、时代或材质风格。
- 将标准角色立绘固定为正面全身、中性无明显情绪、正面站立、双手放松、脚部完整可见。原文“表情自然”与“面无表情”冲突时，以此中性资产模式为准；用户明确要求表情设定图或剧情表演图时，另建非标准变体。
- 将场景概念图固定为空场景；不得出现人物、人群、人影、人体剪影或以尸体充当环境元素。
- 只交付文本视觉规范与绘图提示词。用户同时要求实际出图时，先完成资产规范，再把已确认提示词交给图像生成能力。

## 读取参考

- 开始拆解角色与场景前，读取 [references/asset-rules.md](references/asset-rules.md)，执行资产纳入、去重、变体、推断和连续性规则。
- 准备正式输出或编写绘图提示词前，读取 [references/output-spec.md](references/output-spec.md)，执行字段、顺序、角色立绘和 2x2 空场景提示词规范。
- 完整输出保存为 Markdown 文件时，运行 `scripts/validate_art_direction.py <文件路径> --mode full`；只保存提示词库时改用 `--mode prompts`。修复全部 `ERROR`，逐项复核 `WARNING`。

## 判断工作模式

1. **完整拆解**：用户提供完整剧本、章节或大纲并要求角色与场景资产时，输出宏观分析、全部资产档案和提示词库。
2. **定向拆解**：用户只要求角色、场景、某个章节或指定对象时，只处理该范围，并在开头写明“处理范围”。不要补做未授权部分。
3. **增量更新**：用户提供已有设定表或提示词并要求更新时，以现有资产 ID 为基线，只新增或修改受影响的对象与变体；列出变化及其连续性影响。
4. **风格待确认**：用户未提供画风，且未授权代定风格时，先完成宏观分析与资产档案，提供 2–3 个互斥的画风方向及简短差异，然后停止；不要输出带占位符的“最终提示词”。
5. **授权代定风格**：用户明确说“你来定”“直接做”或同义表达时，根据题材选择一个统一画风，标记 `全局画风（推断）：...`，继续完成提示词。

以下代表性请求应正确进入对应模式：

- 完整输入：“把这份仙侠漫剧剧本拆成角色人设、场景资产，并按国风厚涂生成绘图提示词。”
- 信息缺失：“先从这章小说整理全部人物和场景，画风我还没想好。”——进入风格待确认，不伪造最终提示词。
- 边界请求：“只更新女主雪地战损造型和城门坍塌后的场景，其他资产保持不变。”——进入增量更新，不重写整套资产。

## 处理输入

提取并锁定：

- 剧本、章节、大纲、人物小传或现有视觉设定；
- 用户指定的处理范围、目标画风、时代、地域、媒介和目标绘图平台；
- 用户要求保留的角色名、场景名、资产 ID、服装版本和状态版本；
- 用户允许推断的程度，以及已有禁用元素、画幅、清晰度和生成数量。

缺少剧本文本或等价故事信息时停止，并索取内容。缺少非关键技术参数时采用：角色图 `9:16、2K、建议生成 5 张`；场景 2x2 网格整体画布 `16:9、2K`。平台不支持把数量写进提示词时，将“建议生成数量”保留为独立参数。

若原文内部冲突，按以下顺序处理：

1. 用户当前明确说明；
2. 同一对象较新、较具体的设定；
3. 与剧情事件和连续性一致的描述；
4. 仍无法确定时列出冲突，不静默任选。

## 执行工作流

### 1. 建立宏观视觉基线

识别题材、时代与地域，提炼一句话梗概和简短剧情概述。只在完整拆解模式输出这一部分；定向或增量模式仅保留与目标资产有关的视觉基线。

记录全局画风来源：

- `用户指定：原文画风`
- `沿用既有设定：文件或版本`
- `推断：题材依据`
- `待确认`

### 2. 建立资产清单

按 [references/asset-rules.md](references/asset-rules.md) 遍历文本并建立：

- 角色实体及需要独立出图的年龄、服装、装备、伤势或身份阶段变体；
- 场景实体及需要独立出图的时段、天气、陈设、破坏或剧情状态变体；
- 原文证据、推断项、未知项和彼此关系。

先完成清单再写提示词，避免同一对象重名、漏项或前后矛盾。默认纳入主要角色、复现角色、关键一次性角色与承担剧情功能的独特场景；普通群众和无视觉辨识度的过场地点不单独建资产，除非用户要求。

### 3. 编写角色视觉档案

为每个角色或独立造型变体分配稳定 ID。锁定身份定位、年龄感、面部、发型、体型、服装层次与材质、鞋履、关键配件、标志性道具、人物关系和连续性状态。

把未被原文支持的补全逐项标注为推断。不要用“英俊”“漂亮”“高级感”等空泛词代替可画出的五官、轮廓、颜色、材质和穿法。

### 4. 编写场景视觉档案

为每个场景或独立状态变体分配稳定 ID。锁定时间与空间功能、地面和材质、前景入口、中景主体、背景边界、天空或顶部结构、关键陈设、光源方向、色温、天气、氛围和事件后的连续性状态。

同一地点的不同时间或破坏阶段优先建立状态变体；空间结构本身不同或无法由同一底图派生时才建立新场景实体。

### 5. 生成角色立绘提示词

只在全局画风已确定后生成。按 [references/output-spec.md](references/output-spec.md) 的顺序，把角色稳定特征与当前变体写进一段自然语言提示词。

确保单人、正面、全身、中性无明显情绪、脚部完整、纯净高级灰背景和柔和影棚光彼此兼容。标志性手持道具只采用静态安全持法；需要动态姿势、表情组或多角度转面时另建扩展资产，不污染标准立绘。

### 6. 生成场景 2x2 概念图提示词

为每个场景状态变体各写一段提示词。严格按“风格与网格定义 → 时间与地点 → 地面与材质 → 光影 → 前景 → 中景/主体 → 背景 → 天空/顶部与氛围 → 技术参数”的顺序。

明确四格是同一地点、同一时刻、同一陈设状态的顶视鸟瞰、正面、左侧和右侧视图；要求空间布局、建筑结构和关键道具位置一致。室内场景用天花、穹顶或顶部结构替代天空，不强行添加室外元素。

### 7. 质量复核

逐项检查：

- 关键角色与不同场景是否不重不漏，ID 和编号是否连续；
- 原文事实、推断和未知是否清楚分开；
- 角色面貌、服装、配件、伤势和状态是否能跨资产延续；
- 场景空间、材质、光线、道具和破坏状态是否一致；
- 角色提示词是否适合作为标准资产，而非剧情动作镜头；
- 每个场景提示词是否含 2x2 四视角、分层空间词、无人物限制和统一技术参数；
- 是否存在互斥画风、矛盾机位、未替换占位符或模型无法同时执行的要求。

按 [references/output-spec.md](references/output-spec.md) 交付。不要附加与任务无关的寒暄、角色扮演称呼或伪造的“已生成图片”声明。
