# TimeAIGC_Seedance 2.5 打斗分镜

## 锁定能力边界

- 把“约 30 秒一段、每段 16 个动态镜头”作为本 Skill 的工作流规格，不宣称它是 Seedance 2.5 的平台硬限制。用户提供明确的平台参数时，以用户参数为准，并指出与本规格的差异。
- 专注会改变位置、姿态、攻防关系和环境状态的连续打斗。不要把 16 镜写成 16 个孤立帅姿或九宫格关键帧。
- 不调用外部生成服务，不生成图片或视频；只交付动作段落与中文镜头提示词。
- 第二阶段不输出台词原文。若台词是剧情关键节拍，保留说话动作、口型和对手反应，但不写出台词文本；除非用户明确要求改为含对白版本。

## 读取参考

- 设计或改写动作链前，读取 [references/combat-design.md](references/combat-design.md)，按战斗类型处理发力、距离、武器轨迹、环境互动和状态延续。
- 输出正式段落或 16 镜前，读取 [references/output-spec.md](references/output-spec.md)，使用对应格式和计时规则。
- 生成 16 镜草案后，运行 `scripts/validate_storyboard.py`；结构校验通过后仍须人工检查动作因果、空间和忠实度。

## 判断入口

1. **从设定设计战斗**：用户给出人物、场景、战斗目标或参考图，但没有可直接拆镜的定稿段落。进入阶段一，按总时长设计一个或多个约 30 秒段落。
2. **直接拆解定稿段落**：用户提供明确段落、指定已有段落，或明确要求跳过段落设计。锁定原事件后直接进入阶段二。
3. **同时要求两阶段**：若需要设计多个段落，先输出阶段一并等待用户选择；若只需设计一个段落且用户明确要求“直接拆成 16 镜”，允许同轮完成两阶段。
4. **修改既有结果**：只修改用户点名的段落或镜头，并同步更新受影响的后续状态、时间轴和连续性说明；不要顺手重写未受影响内容。

不要把“Seedance”“做分镜”等宽泛词单独视为必须采用本规格。出现 13–14 秒、4–9 镜或通用剧情切片时，转用 `timeaigc-seedance2-shot-breakdown`；明确要求 9 宫格时不要擅自改为 16 动态镜头。

## 锁定输入

提取并区分“用户明确提供”“从参考图观察”“为执行所作假设”：

- 剧情事实：冲突起因、双方目标、胜负或段落终点、禁止改变的事件；
- 角色状态：体型、技能、战斗风格、服装、武器、持握手、伤势、情绪；
- 场景拓扑：起始站位、距离、朝向、出入口、障碍物、可破坏物和危险边界；
- 视听要求：画面风格、时代、画幅、光线、氛围、暴力强度；
- 交付范围：阶段一或阶段二、总时长、段落数、指定段落。

若用户提供参考图，逐张查看并记录可见造型、道具和空间事实。最新明确文字要求高于图片推断；无法从图片确认的内容不得写成既定事实。

只有以下缺口会阻止创作：无法识别交战主体、没有任何冲突目标或动作事件、没有可用场景。缺少非关键参数时直接采用保守默认值并在输出前列出“假设”：横屏 16:9、24fps、无新增台词、写实物理基线、暴力强度不超过输入。

## 阶段一：设计约 30 秒动作段落

1. 先建立战斗规则：双方优势、有效攻击距离、武器或能力边界、胜负条件和不可逾越的设定。
2. 根据核心交战双方的体型、能力、武器、性格和战术差异，生成一段“全局通用混打提示词”。分别描述双方稳定的动作风格、速度或力量质感、战斗效果和典型视觉反馈，再描述两者交锋时可复用的整体节奏、打击感、运镜倾向、氛围和效果词。
3. 让全局通用混打提示词保持镜头无关：不得写具体招式顺序、站位、移动路线、命中部位、受伤结果、环境破坏事件或胜负；不得把某一段落才发生的事件写成所有镜头的固定要求。按 [references/output-spec.md](references/output-spec.md) 输出一个可直接复制的连续中文段落和分类词语库。
4. 为每段设计可在约 30 秒内演完的动作链：开始状态 → 试探或启动 → 接触 → 防守与位移 → 升级或逆转 → 关键打击 → 反馈 → 阶段性终点。
5. 默认安排至少三次有因果的攻防转换；若原剧情更短、更克制或一击结束，不为凑数添加事件。
6. 让环境参与动作并持续留下结果。玻璃碎裂、武器脱手、伤势、烟尘、地面裂纹等一旦发生，后文必须继承。
7. 用足够细节说明路线、重心、攻击角度、接触点和反馈，不执行“每段至少 1200 字”这类与可拍性无关的凑字要求。
8. 按 [references/output-spec.md](references/output-spec.md) 输出基础设定、全局通用混打提示词、段落时间范围、动作叙事和段尾状态。段落数量由用户总时长和剧情决定，不固定为四段。
9. 输出多个候选段落后停止，请用户选择要拆解的段落；不要预写 16 镜。

## 阶段二：拆成 16 个连续动态镜头

1. 锁定选定段落的事件顺序和段尾结果。允许细化动作，不得新增会改变剧情的新角色、新武器、新能力或新地点。
2. 继承阶段一确认的全局通用混打提示词，把它作为所有镜头共享的全局层。若用户拿定稿段落直接进入阶段二，或旧版阶段一结果没有该提示词，先按相同规则生成一次，不要求用户返回阶段一。每镜只补充该镜具体动作，不逐镜改写全局层；若用户要求每镜提示词都可独立复制，则把同一段提示词原样放在每镜的统一前缀或后缀。
3. 先建立连续性账本：每名角色的起始位置、朝向、姿态、武器、伤势；关键道具；已有环境破坏；目标终点。
4. 将段落拆为动作节拍，再按叙事需要分配 16 镜。不要机械套用“第 7 镜必定关键打击”等固定模板。
5. 建立从 `00:00` 开始、连续无重叠并覆盖目标时长的时间轴。给复杂接触、受击反馈和空间重建足够时长；不要让镜头数正确但动作来不及完成。
6. 每镜只设置一个主要摄影运动意图。明确景别、视角、主体动作、承接点和角色相对位置；大幅位移或越轴前后用可辨认的空间镜头重建方向。
7. 把上一镜结束的姿态、惯性、距离和破坏状态作为下一镜起点。武器不得无故换手或复位，角色不得瞬移，伤势和环境不得无故恢复。
8. 把打击、能量、碎片、烟尘、衣摆或光影等可见反馈写在 `【】` 内，说明出现时机及与动作的关系；没有超自然能力时不要强加能量特效。
9. 按 [references/output-spec.md](references/output-spec.md) 的固定字段顺序输出 16 镜，不残留占位符。
10. 将正式 16 镜保存为 UTF-8 Markdown 临时文件并运行：

```powershell
python scripts/validate_storyboard.py <临时文件> --report
```

修复全部 `ERROR`，逐项复核 `WARNING`，再清理临时文件。若当前环境的 `python` 不可用，使用可用的 Python 3 解释器运行同一脚本。

## 处理冲突

按以下优先级解决约束冲突：

1. 用户最新明确要求；
2. 已锁定剧情事实、角色和参考资产；
3. 动作、空间、时间与物理可执行性；
4. 本 Skill 的 30 秒与 16 镜规格；
5. 风格词、镜头炫技和旧文档示例。

若高优先级要求使 16 镜或目标时长不可执行，明确指出冲突并给出最小调整方案，不要静默删剧情、压缩台词或制造瞬移。

## 交付前人工复核

- 逐镜检查准备、发力、轨迹、接触、反馈和后续状态是否有因果；
- 顺着空间路线复述人物位置、朝向和距离，确认无越轴混乱或瞬移；
- 核对服装、武器持握、弹药或能量、伤势、道具和环境破坏；
- 核对 16 镜时间轴完整覆盖目标时长，动作密度与单镜时长相符；
- 核对镜头语言服务动作，没有互斥机位、焦点或运镜；
- 核对忠实度、字段顺序、编号连续、无台词原文和无占位符。
